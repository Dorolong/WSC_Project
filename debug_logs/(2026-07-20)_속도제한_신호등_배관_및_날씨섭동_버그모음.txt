[ 문제 1 ] pandas Series.clip(min=..., max=...) TypeError
- 증상: scripts/main.py 실행 시
  `TypeError: clip() got an unexpected keyword argument 'min'`
- 원인: 설치된 pandas 버전이 Series.clip()의 min=/max= 키워드를
  더 이상 지원하지 않고 lower=/upper=를 요구함(pandas API 변경).
  CS구간 상관 날씨 섭동 코드(shortwave_radiation, wind_speed_10m
  클리핑) 2곳에서 발생.
- 해결: .clip(min=0) -> .clip(lower=0) 2곳 모두 변경.
- 상태: 수정 완료, 재실행으로 정상 동작 확인(2-trial 스모크
  테스트 성공).

[ 문제 2 ] lookahead_const 참조 미갱신 (NameError)
- 증상: run_simulation() 안 compute_lookahead(step, lookahead_const)
  호출부가 lookahead_const를 참조하는데, 실제로는 const로 딕셔너리
  이름이 변경됨(속도제한 데이터도 같이 담기 위해). NameError 발생
  가능 상태.
- 원인: 딕셔너리 이름을 lookahead_const -> const로 리네임하면서
  이 호출부 한 곳을 갱신 안 함.
- 해결: compute_lookahead(step, const)로 수정.
- 상태: 최소 2회 재확인 필요했음(1차 "고쳤다"는 보고 후 재확인
  시 실제로는 안 고쳐져 있었음, 2차 재확인에서 최종 수정 확인).
  현재 완료.

[ 문제 3 ] const 딕셔너리 키 이름 불일치 (speed_limit_dist vs
  speed_limit_dists)
- 증상: const 딕셔너리는 speed_limit_dist(단수)로 키를 만들었는데
  compute_speed_limit()은 const["speed_limit_dists"](복수)로 조회
  -> KeyError 유발 가능.
- 원인: 딕셔너리 생성부와 조회부를 따로 작성하며 이름 스펠링이
  갈림.
- 해결: 양쪽 다 speed_limit_dists(복수)로 통일.
- 상태: 수정 완료.

[ 문제 4 ] app.py load_data() 반환값 개수 불일치
- 증상: load_data()의 return문이 7개 값만 반환하는데, 호출부
  unpacking은 9개 변수를 기대 -> ValueError: not enough values to
  unpack.
- 원인: 호출부는 이미 속도제한 데이터를 받을 준비가 돼 있었는데,
  load_data() 내부에 실제 속도제한 CSV 로딩 코드가 아직 추가 안 됨.
- 해결: load_data() 안에 speed_limits_df 로딩 + return 튜플에
  speed_limit_dists/speed_limit_vals 추가.
- 상태: 수정 완료.

[ 문제 5 ] app.py 반환문 오타 (speed_limits_dists vs
  speed_limit_dists)
- 증상: 문제 4 수정 직후, load_data()의 return문이
  speed_limits_dists/speed_limits_vals('s' 추가된 오타)를
  참조하는데 실제 로컬 변수명은 speed_limit_dists/speed_limit_vals
  (단수) -> NameError.
- 해결: return문을 로컬 변수명(단수)에 맞춰 수정.
- 참고: 이후 호출부(unpacking, run_simulation() 호출)는
  speed_limits_dists(복수)라는 이름으로 받아 쓰는데, 이건 파이썬
  unpacking이 이름표를 새로 붙이는 것뿐이라 문제 없음(load_data()
  내부 이름과 바깥 받는 이름이 달라도 무방) - 실제 로직 오류가
  아니라 단순 명명 비일관성으로 확인, 개수/참조만 맞으면 정상.
- 상태: 수정 완료, 최종 확인.
