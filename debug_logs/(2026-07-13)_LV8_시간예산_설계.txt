================================================================
(2026-07-13) LV8 시간 예산 규칙 - 설계와 두 번의 재설계
================================================================

[ 배경 ]
trial_2_260712의 best 트라이얼(#158, 99.57%)을 재실행해서 분석한 결과:
- 종료 시점 DY=27, HR=17 (허용된 마지막 날 마지막 시간)
- 종료 시점 SOC 0.58 (58%, 완전히 여유 있는 상태)
- 종료 직전 여러 스텝 동안 속도가 정확히 v_min에 고정
=> 에너지 문제가 아니라 시간 문제. 일몰 무렵 LV3(일사량 보정)이 SOC
여유와 무관하게 항상 감속시켜서, 배터리가 남아도 완주 직전에
불필요하게 느려지는 구조적 문제로 진단.

[ 버전 1: 하드 스위치 ]
run_simulation에서 remaining_drive_hours(오늘 남은 시간 + 남은 날짜*9h)와
remaining_race_dist로 required_race_pace 계산해서 mpc_speed()에 전달.
    elif soc > params.get("LV8_soc_min", 0.4):
        v = max(v, required_race_pace * params.get("LV8_time_margin", 1.05))
검증 결과 심각한 문제 발견: required_race_pace가 레이스 시작부터 이미
시속 67km/h대(3038km/45시간)라서, SOC가 낮아 LV1_V3(보수 티어)로
가야 할 때도 이 규칙이 강제로 속도를 끌어올림. mpc_default_params로
테스트했더니 원래 59%까지 가던 게 24%에서 SOC 하한 걸려 조기 실격
(오히려 악화). LV1_soc2 이하에서는 개입 안 하도록 게이트 추가해서 1차
완화 (mpc_default_params 재테스트 시 원래 59%와 동일하게 복귀 확인).

[ 버전 2: LV8_soc_min을 Optuna 탐색 파라미터로 분리 ]
게이트 임계값을 LV1_soc2에 얹혀가지 않고 독립 파라미터 LV8_soc_min으로
분리해서 Optuna가 따로 찾게 함. 93트라이얼 진행 후 best(#63, 98.77%)를
재실행 분석: 종료 시점 SOC 25.65%인데, 이 트라이얼의 LV8_soc_min이
0.5395로 튜닝되어 있어서 SOC가 그 밑으로 떨어진 순간 LV8이 완전히
꺼져버림 -> 같은 "v_min 눌림" 패턴이 낮은 SOC에서 재발. 임계값을 어디에
잡든 그 바로 아래서 같은 문제가 재발하는 On/Off 스위치 방식 자체의
구조적 한계로 결론.

[ 버전 3: 스무스 블렌드 (최종) ]
하드 스위치를 완전히 제거하고 연속적인 가중평균으로 재설계:
    soc_cutoff = params.get("soc_cutoff", 0.15)
    if soc <= soc_cutoff:
        v = params.get("v_min", 45)
    else:
        urgency = clip((required_race_pace - v) / v, 0, 1)      # 목표 대비 얼마나 부족한지
        soc_factor = clip((soc - soc_cutoff) / params.get("margin", 0.5), 0, 1)  # SOC 여유 정도
        global_factor = urgency * soc_factor
        v = (1 - global_factor) * v + global_factor * required_race_pace

디버깅 과정에서 실제로 두 개의 구현 버그가 있었고 수정함:
  1) np.clip() 괄호 실수로 인자가 튜플 하나로 묶여 TypeError
     (np.clip((x, 0, 1)) 형태로 잘못 작성됨)
  2) 연산자 우선순위: `soc - a / b`가 `(soc-a)/b`가 아니라 `soc-(a/b)`로
     계산되는 문제 (괄호 명시적으로 추가해 해결)
LV8_soc_min, LV8_time_margin(구버전 파라미터) 제거, margin(0.1-0.6)
하나로 통합.

[ 작동 원리 메모 ]
매 스텝의 개입 비율(global_factor)은 작지만, 15만 스텝에 걸쳐 항상
같은 방향으로 누적됨. 반면 LV2/LV3 같은 로컬 보정은 오르막/내리막,
맑음/흐림에 따라 방향이 바뀌면서 장기적으로 상쇄되는 경향이 있어,
작은 지속적 개입이 장기 평균 속도에는 확실한 영향을 줌.
