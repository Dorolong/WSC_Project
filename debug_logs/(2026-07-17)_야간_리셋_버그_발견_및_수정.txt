[ 배경 ]
trial_10 (LV1을 계단형에서 램프로 전환한 직후 라운드) 50개 트라이얼
완료 후 결과 확인. best trial 도달률 약 93.9%까지 개선됐으나 5개
고정 날씨 전부 완주 실패(SOC 하한선에서 정지). LV1 램프 전환만으로는
설명이 안 되는 수준의 정체라 판단, run_simulation() 전체 코드를
처음부터 다시 리뷰함.

[ 발견 경위 ]
야간 데이터 처리 블록에서 문제 발견:
    if HR < 8 or 17 <= HR:
        if 17 < HR:
            next_day = (DY - 23) + 1
        else:
            next_day = DY - 23   # HR==17인 경우 여기로 빠짐
        Accum_s = next_day * 86400
        continue
HR이 정확히 17일 때 "다음날 8시"가 아니라 "같은 날 8시"로 리셋됨.
`17 < HR`과 `17 <= HR`을 섞어 쓰다가 생긴 경계값 버그로 추정(리팩터링
과정에서 조건 통일이 안 된 것으로 보임).

[ 사용자 검증 요구 ]
버그를 보고하자 사용자가 두 차례 반문함:
  - "이게 993이나 차이가 날 수 있다고?"
  - "근데 일사량이 달랐는데" (같은 조건 비교가 맞는지 의심)
주장만으로 끝내지 않고 실제 데이터로 증명하기로 함.

[ 검증 방법 ]
Vehicle_Function_buggy.py(버그 재현 사본)를 별도로 만들어 동일
mpc_default_params, 동일 env_data로 FIXED/BUGGY 버전을 나란히
run_simulation() 실행하는 A/B 테스트 스크립트(ab_test_bug.py) 작성.

[ 결과 ]
- FIXED: 143242 rows, 최대 도달거리 2864.6km
- BUGGY: 93595 rows, 최대 도달거리 1871.7km (약 993km, 35% 차이)
- 버그 트리거 지점: dist=601.2km, 1172.9km, 1683.4km (전부 HR==17)
- 100km 지점별 DY 비교: 700km 지점부터 FIXED는 DY24로 정상 진행하는
  반면 BUGGY는 1800km 지점까지도 DY23(1일차)에 갇혀 있음
- 평균 P_gen: FIXED 970.3W vs BUGGY 1044.3W (버그 버전이 실제보다
  "일사량이 좋은 시간대"를 반복 재사용하고 있었음 - 두 번째 반문에
  대한 답: 날씨가 달랐던 게 아니라 버그 버전이 잘못된 시간대의
  일사량을 계속 갖다 쓴 것)

[ 원인 해석 ]
HR==17에서 리셋이 안 되니 시뮬레이션 내부 시계(DY)가 실제 주행
거리보다 계속 뒤처진 채 고착. 그 결과 실제로는 여러 날짜에 걸쳐
있어야 할 구간을 전부 1일차(DY23) 시간대 일사량으로 계산하게 되어
누적 오차가 커짐. trial_9/trial_10 전체가 이 버그가 있는 상태로
평가된 것이므로 두 라운드 결과 모두 신뢰 불가.

[ 수정 ]
    if HR < 8 or 17 <= HR:
        if HR < 8:
            next_day = (DY - 23)
        else:
            next_day = DY - 23 + 1
        Accum_s = next_day * 86400
        continue
HR<8과 17<=HR 두 케이스를 명확히 분리.
