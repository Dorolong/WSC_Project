(2026-07-13) 컨트롤스탑 마감시각 실전값 반영 및 실격로직 재설계

[ 배경 ]
debug_logs/(2026-07-13)_컨트롤스탑_규칙_추가.txt 시점에는 컨트롤스탑
마감/오픈시간/구간평균속도 규칙이 구현만 되고 CS_open_hour가 전부 8시
placeholder라 비활성화 상태였음. 2025 BWSC 실제 대회 PDF(Route Notes)
값을 반영해서 활성화하기로 함.

[ 설계 결정 ]
1) CS_open_hour/CS_close_hour를 "8/23 00시 기준 경과시간(시간 단위)"으로
   인코딩하기로 결정. 기존 방식(0~23시 hour-only 비교)은 도착 날짜(DY)를
   무시하고 그 시각(HR)만 비교해서, 예상과 다른 날짜에 도착하면 비교
   자체가 무의미해지는 맹점이 있었음. 경과시간 하나로 합치면 날짜+시각이
   자동으로 반영됨.
   - 기준을 "8/23 08:30(실제 출발시각)"이 아니라 "8/23 00:00"으로 잡음
     -> 코드의 total_s(= 8*3600 + Accum_s)가 이미 이 기준으로 계산되고
     있어서 별도 보정(-1800) 없이 직접 비교 가능.
2) Control_Stop_2025 거리값도 PDF 정밀값으로 교체
   (1212000->1212300, 2720000->2720500 등)
3) day_end_dist(일자별 목표거리) 필드 제거, CS_close_hour로 완전히 대체.
   실격 판정을 "그날 목표거리 못 넘으면"이 아니라 "그 CS 도착 시점에
   마감시각을 넘었는지"로 재설계 (규정 원문과 더 일치, debug_logs/
   (2026-07-13)_컨트롤스탑_규칙_추가.txt 참고).
4) 사용자가 PDF에서 직접 추출한 값을 Configs/Vehicle_Params.py에 입력.
   Functions/Vehicle_Function.py 쪽 로직은 여러 라운드에 걸쳐 코드
   리뷰하며 버그를 순차적으로 발견/수정함 (아래).

[ 발견/수정된 버그 목록 ]
1. full_Days 오타 (정의는 full_days) -> NameError
2. 줄 끝 `/` 뒤 줄바꿈만 하고 괄호/백슬래시 없음 -> SyntaxError
3. drivable_hours_until() 호출 시 키워드 인자명이 함수 정의(target_h)와
   불일치(Final_finish_HR로 잘못 씀) -> TypeError
4. 한글 주석에 `#` 누락 -> SyntaxError
5. **cs_hit 스테일 참조**: 컨트롤스탑 마감 체크가 원래 야간 처리 블록
   안에 있었는데, 그 시점엔 cs_hit이 이번 스텝 값으로 아직 계산 안 됨
   (계산은 코드 뒤쪽에서 일어남) -> 이전 루프의 stale 값을 참조하거나
   최초 실행 시 UnboundLocalError. 해결: 마감시각 체크를 `if cs_hit:`
   블록 안(cs_hit이 방금 막 계산된 진짜 값인 지점)으로 이동.
6. next_cs 폴백 기본값 단위 오류: `default=3038`로 3자리가 빠져서
   마지막 CS 이후 remaining_dist가 큰 음수가 됨 -> `race.total_distance`
   (3038326)로 수정.
7. `race.Control_Stop_2025[2720500]`가 거리->CS이름 딕셔너리라 문자열
   "CS9"을 반환, curr_dist(float)와 비교 시 TypeError -> 리터럴
   `2720500`과 직접 비교하는 방식으로 수정.
8. **가장 심각한 버그 - 순수주행시간 미분리**: 구간평균속도 실격 체크의
   leg_time_hr이 Accum_s(벽시계 기준 누적시간, 야간에 다음날 08시로
   점프하는 로직과 공유되는 변수)로 계산되고 있었음. 하루 안에 못 끝나는
   구간(예: CS2->CS3, 357km)은 야간 점프분(약 14~15시간)까지 "주행
   시간"에 그대로 합산되어, 실제 주행 속도(74~75km/h)와 무관하게 무조건
   실격 처리됨. Optuna 150개 트라이얼 전부 파라미터와 무관하게 정확히
   CS3(988km) 지점에서 동일한 objective 값으로 실격되는 현상으로 발견
   (파라미터가 다른데 결과가 완전히 같다는 게 단서였음).
   -> drive_time_s라는 별도 누적 변수 신설. 매 스텝 dt만큼 증가하되
   야간 점프(Accum_s = next_day*86400)에는 영향받지 않음. 구간평균속도
   체크는 이제 drive_time_s 기준, last_cs_time도 drive_time_s 스냅샷.
   Accum_s/total_s는 기존대로 날짜·마감시각 판정용으로만 사용.
   수정 후 동일 파라미터로 재실행하니 987km -> 2181km까지 진행 확인.
