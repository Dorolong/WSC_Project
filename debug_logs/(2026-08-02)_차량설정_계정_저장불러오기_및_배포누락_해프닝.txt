progress/28(전역상태 격리 버그수정) 배포 직후, 사용자가 "이거 혹시
각자 사용자들이 앱에서 바꾸고 새로고침하면 다시 초기화되는거야?
각자 세팅값 불러오기 버튼 이런걸로 자기 마지막에 했었던 세팅
불러올 수 있었으면 좋겠는데. 그리고 자기가 실행했던 기록들 누르면
그거 세팅값 불러오는 기능도 있었으면 좋겠다"라고 질문 - 세션 격리는

보완하는 요청.

[ 설계 확인 및 SQL ]
계정(Supabase) 기반 저장/불러오기로 방향 잡고 사용자 확인받은 뒤 SQL
전달:
- 신규 user_settings 테이블(사용자당 1행, vehicle_cfg jsonb, RLS
  "for all" 정책 하나로 select/insert/update 커버)
- 기존 simulation_runs에 vehicle_cfg 컬럼 추가(그 실행 때 쓴 제원도

[ 직렬화 설계 고민 ]
cfg(SimpleNamespace로 묶은 7개 dataclass, numpy 배열 포함)를 어떻게
JSON에 안전하게 저장/복원할지가 핵심 문제:
- dataclasses.asdict()가 "선언된 필드만" 뽑아준다는 점을 활용 -
  pack/drive의 __post_init__()이 계산한 파생값(HV_Energy, v_max 등)
  은 dataclass field로 선언 안 돼있어서 asdict() 결과에 자동으로
  안 들어감. 저장 용량도 아끼고, 복원 시 __post_init__() 재호출로
  항상 최신 계산값을 보장(저장 시점 파생값이 stale해질 걱정 없음).
- numpy 배열(cell.ocv_soc/ocv_V)은 재귀적으로 .tolist() 변환.
- 복원은 build_default_cfg()를 베이스로 값만 덮어쓰는 방식 - 나중에
  차량 제원 필드가 추가돼도 옛날에 저장된 데이터에 그 필드가 없으면
  그냥 기본값으로 채워짐(하위 호환).
- pack.Cell 문제: build_default_cfg()가 이미 pack.Cell = cell(같은
  인스턴스 참조)로 만들어두므로, 복원 시 pack.Cell을 따로 처리할
  필요 없이 HV_S/HV_P/LV_S/LV_P만 복원하고 pack.__post_init__()만
  다시 불러주면 자동으로 올바르게 연결됨.

[ 검증 ]
스크래치패드 테스트: mass=275.5, HV_S=42, ocv_V*1.01로 임의 변경 ->
cfg_to_jsonable() -> json.dumps()(에러 없이 성공, numpy 등 비직렬화
객체 안 남음 확인) -> json.loads() -> cfg_from_jsonable() 순서로
round-trip. mass/HV_S 값 일치, HV_Energy가 바뀐 HV_S 기준으로 정확히
재계산됨(2592.0 -> 2721.6), ocv_V 배열 일치, pack.Cell is cell(참조
관계 유지) 확인, race의 dict 필드(Control_Stop_2025) 보존, 빈 dict
입력 시 기본값 폴백까지 전부 확인.

[ 해프닝 - push 깜빡함 ]
구현·테스트 다 끝내고 SQL을 먼저 사용자에게 전달, "SQL 실행하시면
커밋·푸시할게요"라고 말해둔 상태에서 사용자가 SQL 실행 완료를
알려왔는데, 그 직후 사용자가 배포된 앱에서 별개의 NameError
(build_default_cfg 관련, 실제로는 이전 커밋이 이미 정상 반영돼
있었고 Streamlit Cloud 쪽 배포 지연/재부팅 필요 이슈로 확인됨)를
문의해서 그 대응에 정신이 팔린 사이 이번 기능의 실제 git push를
깜빡함. 사용자가 "제원 불러오기 칸이 안 보이는데"라고 재문의해서야
git status로 확인하고 뒤늦게 커밋·푸시.
**교훈**: 기능 구현 완료 후 사용자의 후속 액션(SQL 실행 등)을
기다리는 중간 단계가 있으면, 그 사이 다른 이슈가 끼어들 때 push를
잊기 쉬움 - progress/31 백로그에 재발 방지 메모 남김("완료했다"고
보고하기 전 커밋·푸시까지 반드시 끝낼 것).
