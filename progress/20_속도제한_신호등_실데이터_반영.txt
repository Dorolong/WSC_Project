[ 구현 - Functions/Vehicle_Function.py ]
- light_arrive(curr_dist, light_dists, visited_lights): cs_arrive()와
  같은 point-event 패턴이나, light_dists 값 자체가 dict-unique하지
  않을 수 있어 enumerate() 기반 인덱스로 visited 추적(cs_arrive()는
  거리값 자체로 추적).
- compute_speed_limit(step, const): np.searchsorted(speed_limit_dists,
  curr_dist_km, side="right") - 1, idx = max(idx, 0) 로 계단형 룩업.
  매 스텝 재평가(한 번 지나가면 끝나는 point-event 아님, CS/신호등과
  다른 패턴).
- run_simulation() 루프 안, control_stop_handler() 처리 직후:
  light_hit = light_arrive(...) -> visited_lights.add() ->
  Accum_s += simpara.avg_traffic_light_delay(15s) 또는
  avg_pedestrian_light_delay(10s).
- const 딕셔너리에 speed_limit_dists/speed_limit_vals 추가(당시엔
  route 세그먼트 데이터 없었음, 이후 progress/22에서 is_downhill/
  is_uphill도 같은 자리에 추가됨).

[ 알려진 버그 - 아직 미수정 ]
**light_arrive() 단위 불일치**: 호출부(run_simulation() 559행)에서
`light_arrive(step["curr_dist"], light_dists, visited_lights)`로
호출하는데, step["curr_dist"]는 **미터** 단위(route_dist 배열,
예: 322000)인 반면 light_dists는 traffic_lights_2025.csv의
distance_km 컬럼 그대로라 **km** 단위(예: 12.5). light_arrive()
내부 비교(`abs(curr_dist - light_dist) < 20`)가 단위 안 맞는 두
값을 그대로 빼고 있어, 사실상 신호등이 절대 트리거되지 않는 상태
(예: |322000 - 12.5| ≈ 321987, 20보다 훨씬 큼). cs_arrive()는
control_stops가 미터 단위라 정상 작동, compute_speed_limit()는
curr_dist_km = curr_dist/1000 변환을 거쳐서 정상 작동 - light_arrive()
에만 이 변환이 빠짐. 발견 시점: 2026-07-20(문서화 직전 재검증
중), 사용자 판단으로 지금은 고치지 않고 백로그로만 남김
(progress/27 참고). 고치는 법은 light_arrive() 안에서
curr_dist_km = curr_dist/1000 변환 후 비교하거나, 호출부에서
step["curr_dist"]/1000을 넘기면 됨.

[ 상태 ]
법정 속도제한은 정상 작동 확인. 신호등 지연은 **코드는 존재하나
단위 버그로 실제로는 발동 안 함** - 다음 세션에서 고칠 것.
