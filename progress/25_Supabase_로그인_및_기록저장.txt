[완료] Supabase 로그인 + 시뮬레이션 기록 저장/조회
================================================================
완료일: 2026-08-02

[ 배경 ]
Streamlit 배포 이후, 결과를 웹에 기록하는 기능이 필요하다는 요청.
AI 분석 보조(Claude API 연동)도 검토했으나, 공개 앱에 열면 방문자가
API를 호출할 때마다 앱 소유자 계정의 실제 비용이 나가는 구조라
사용자가 포기 - 대신 결과 저장/조회 + 규칙 기반 분석(progress/26)
으로 방향을 잡음.

[ Supabase 프로젝트 ]
사용자가 사전에 Supabase 프로젝트 생성 완료. Project URL/anon-
publishable key를 전달받아 조립(https://<project-ref>.supabase.co).
anon/publishable 키는 클라이언트 노출을 전제로 설계된 키라 채팅에
직접 공유해도 안전(RLS가 실제 보안 담당) - service_role 키는 절대
사용 안 함.

[ DB 스키마 (Supabase SQL Editor에서 실행) ]
simulation_runs 테이블: id(uuid), user_id(uuid, auth.users FK),
created_at, params(jsonb), completion_ratio, avg_speed_kmh,
final_soc, final_dist_m, notes. RLS 활성화 + "본인 기록만 조회/저장"
정책(auth.uid() = user_id) 적용 - 앱 코드에 버그가 있어도 DB
레벨에서 다른 사용자 기록 접근을 막음.

[ 구현 - app.py ]
- supabase-py 설치, requirements.txt 갱신(geopandas 자산생성 전용
  스택은 계속 제외).
- .streamlit/secrets.toml(SUPABASE_URL, SUPABASE_KEY)에 키 저장,
  .gitignore에 추가(컴퓨터마다 새로 생성 필요 - SETUP.md에 문서화).
- **Supabase 클라이언트를 st.session_state에 세션별로 저장** -
  @st.cache_resource로 캐싱하면 서버 프로세스 전체가 클라이언트
  인스턴스 하나를 공유하게 되어, 로그인 시 클라이언트 내부에 쌓이는
  인증 세션이 다른 사용자 요청에도 섞여 들어가는 위험이 있어 의도적
  으로 세션별 인스턴스로 격리(멀티유저 배포를 염두에 둔 설계 판단).
- 사이드바에 로그인/회원가입 탭, 회원가입 시 닉네임 필드 추가
  (Supabase Auth의 user_metadata에 저장, 별도 테이블 불필요) -
  로그인하면 "{닉네임}님 반갑습니다!" 표시.
- "닉네임 수정" expander 추가(사용자 본인 세션으로 update_user()
  self-service 호출) - 대시보드의 User Metadata 패널이 읽기 전용
  이라 직접 수정이 안 되는 문제를 앱 자체 기능으로 해결.
- 사이드바 "내 시뮬레이션 기록" expander: 최근 20개 조회, 일시를
  YY.MM.DD HH:MM(Asia/Seoul 변환) 형식으로 축약 표시.

[ 발견/수정된 버그 ]
- **로그인 안 해도 실행 가능했던 문제**: "실행" 버튼에 로그인 여부
  disabled 조건 추가.
- **결과 화면이 버튼 클릭 시 사라지는 구조적 문제**: 원래 코드는
  df/그래프/저장버튼이 전부 `if st.session_state.sim_running:`
  블록 안에 있어서, CSV 저장 버튼 등을 눌러 rerun이 발생하면
  sim_running이 이미 False라 그 블록 전체(df 포함)가 스킵되어
  결과 화면이 통째로 사라지는 문제. df/params/reason/최종위치를
  st.session_state(last_df 등)에 저장하고, 결과 표시를 별도의
  `if st.session_state.last_df is not None:` 블록으로 분리해서
  버튼 클릭 rerun에도 화면이 유지되도록 구조 변경.
- **자동 저장 -> 명시적 저장 버튼으로 변경**: 최초엔 시뮬레이션
  완료 시 자동으로 Supabase에 기록했으나, 사용자가 "CSV 저장 버튼
  누를 때만 기록되는 것 같다"고 지적(실제로는 별개 로직이었지만,
  사용자 의도상 명시적 제어를 원함) - "결과 서버에 저장" 버튼을
  CSV 저장 버튼 옆에 별도로 만들어 명시적으로 트리거하도록 변경
  (last_saved 플래그로 중복저장 방지).
