[완료] dist_vals가 pandas Index라 느렸던 성능 버그 수정
================================================================
완료일: 2026-07-20

[ 배경 ]
Optuna 트라이얼 하나당 8분씩 걸리는 게 이상하다는 문제 제기로
cProfile 프로파일링 진행. 상세 과정은
debug_logs/(2026-07-20)_dist_vals_pandas_Index_성능버그_발견_및_수정.txt
참고.

[ 원인 ]
scripts/main.py에서 `dist_vals`를 pandas Index 객체로 만들고
`.to_numpy()`를 안 붙여서, `compute_lookahead()`의 N-포인트
샘플링 루프 안 `dist_vals - future_dist_m` 연산이 매번 pandas의
무거운 내부 경로(타입체크/dtype추론/새 Index 생성/isna 체크)를
탔음. 스텝당 N번(2~5회), 총 약 30만 번 호출되며 누적.
프로파일링(날씨 1개, K=1) 기준 compute_lookahead()가 전체 실행
시간의 74%(158초/214초)를 차지하고 있었음.

[ 수정 ]
```python
dist_vals = env_data.index.get_level_values("total_distance_m").unique().sort_values().to_numpy()
```
`.to_numpy()` 한 줄 추가.

[ 검증 ]
동일 조건 재측정: **214초 -> 51.3초 (4.2배 개선)**. 완주율/거리
(80.0%, 2,431,951m)와 처리 스텝 수 완전 동일 - 로직/결과 영향
없이 순수 속도만 개선.

- 순수 파이썬 max()/min()으로 바꾸면 추가 개선 가능하나, 4배 이상
개선된 현재 상태로 우선 충분하다고 판단해 미적용.
