**2순위 [트랙 B] MPC 물리 building block 완성 (설계 완료, progress/22 스펙)**
1. [완료] 내리막 세그먼트 경계 배열 추출 - scripts/main.py 112~130줄.
   **단 app.py에는 아직 같은 전처리가 없고**, 아래 2번이 없어서 실제로는
   계산만 하고 미사용 상태.
2. compute_downhill_cap(step, const) (Vehicle_Function.py, 사용자 직접
   작성): 세그먼트 진입 전 목표속도 상한 계산.
   a_coast=(F_aero+F_roll+F_slope)/mass,
   v_entry_max = sqrt(v_exit_cap² - 2·a_coast·L).
   mpc_speed()에서 speed_limit과 같은 방식으로 v=min(v, downhill_v_cap).
   **physics/drive는 전역이 아니라 const["physics"], const["drive"]에서
   읽을 것 - progress/28 이후 구조.** 이게 되면 세그먼트 배열을 const에
   실어 넘겨야 하고, app.py에도 같은 전처리 추가 필요.
3. CS 접근 코스팅/제동 (Vehicle_Function.py, mpc_controller.py, 사용자
   직접 작성): coast_distance=v²/(2·a_coast) 트리거로 가속 해제,
   내리막 등 a_coast<=0 구간은 simpara.decel_brake로 같은 공식.
   코스팅/기계제동 중 P_batt는 power.P_LV_race만 반영(배터리 안 거침).
4. [완료] simpara.decel_brake 상수 추가됨(Vehicle_Params.py 193줄,
   0.7g) + app.py "시뮬레이션 설정" 탭에서 편집 가능. **단 아직 물리
   로직 어디에서도 안 씀** - 위 3번에서 사용 예정.
5. [완료] light_arrive() 단위 불일치 버그 수정(progress/39) - 이제
   실제로 신호등 지연이 발동함(43개 감지, 중복 방지 확인).
6. 위가 다 되면 본격 Optuna 재탐색(이제 웹 런처로 돌릴 수 있음. CLI로 돌릴 거면

   - Supabase anon key 하드코딩(공개 레포)은 아직 남음. RLS 전제하에
     공개돼도 되는 값이라 급하진 않으나, progress/46 "이번 범위에서
     뺀 것"에 레이트리밋과 함께 다음 기획 대상으로 적어둠.
5. 서버 재시작 시 진행 중이던 탐색 상태가 사라짐(RUNS/QUEUE가 메모리
   전용). 완료 결과는 파일+Supabase에 남으므로 치명적이진 않음.

[ 4순위 - 예전부터 보류 중이던 항목 ]
1. 속도값 정수(int) 출력 반영 - 내부 계산은 float 유지, 반올림은
   results.append() 시점에만. 결정만 되고 미반영.
2. momentum_gain을 Optuna 탐색공간에 넣을지 - 본 탐색 재실행 때 결정.
3. (선택) mpc_speed()의 np.clip() 스칼라 호출을 max()/min()으로 교체.
4. termination_reason을 objective() 스코어링에 활용할지 검토 - 현재는
   받기만 하고 안 씀. 실격 유형별로 다른 페널티를 주면 탐색이 더
   정교해질 수 있음.
5. Optuna 트라이얼 병렬화 - 웹 런처가 프로세스 분리로 이미 부분 해결.
   서버 사양을 올리면 WSC_MAX_CONCURRENT를 올리는 것으로 확장 가능.

[ 방향 메모 - 룰베이스 -> 비용함수 MPC 전환 ]
현재 전략은 룰베이스 기반 MPC를 먼저 물리적으로 말이 되게 완성한 뒤,
각 룰 항을 비용함수와 제약조건으로 재구성하는 것. LV4의 균등 SOC
배분 문제는 인지하고 있지만 당장 삭제하지 않고, building block 검증
후 비용함수 전환 단계에서 다시 설계한다.
없는 것: 명시적 예측 모델 기반 수치 최적화(매 스텝 비용함수를 실제로
풂), 명시적 objective function, 제약조건을 최적화 내부에서 다루는 것
(현재는 soc_cutoff/v_max/speed_limit 전부 사후 클리핑).
있는 것: receding horizon(매 스텝 상태 재측정 후 재계산), 상태 피드백,
부분적 예측(avg_gen_ratio, slope_ahead).
오르막은 배터리 I²R 손실 기반 비용항으로, energy_crit의 균등배분
가정도 지형 기반 1회성 예산 배분으로 재설계 예정(progress/22).
