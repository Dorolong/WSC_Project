[완료] 차량 제원 설정이 전역 상태로 새던 멀티유저 버그 수정
================================================================
완료일: 2026-08-02

[ 배경 ]
사용자가 배포된 앱을 살펴보다 직접 발견: "누군가가 MPC 최적
parameter를 건들면 모든 사용자에게 이게 global 수정이 돼. local으로
되는 게 아니라". 실제로는 MPC 튜닝 파라미터(slope_k 등, 사이드바에
읽기 전용으로만 표시됨)가 아니라 "차량 제원 설정" 다이얼로그
(physics/solar/cell/pack/power/drive/race)가 문제였음.

[ 원인 ]
`Configs/Vehicle_Params.py`의 physics/solar/cell/pack/power/drive/
race가 **모듈 로드 시 한 번만 생성되는 전역 싱글턴**. Streamlit
Cloud는 앱 하나당 서버 프로세스 하나를 여러 사용자가 공유하는
구조라(st.session_state만 사용자별 격리, 모듈 전역은 프로세스 전체
공유), `app.py`의 "적용" 버튼이 `physics.mass = mass`처럼 전역
객체를 직접 mutate하면 그 순간 그 서버에 붙어있는 **모든 사용자**
에게 반영됨.

[ 기각한 대안 ]
"적용 누른 사람 값으로 잠깐 바꿨다가 시뮬레이션 끝나면 원복" 같은
임시 방편은 진짜 경쟁조건(race condition) 버그라 기각 - Streamlit은
사용자별 스크립트 실행을 별도 스레드로 돌리기 때문에, 복구되기 전
찰나에 다른 사용자의 동시 실행이 그 값을 읽어버릴 수 있음(GIL이
있어도 스레드 간 끼어들기는 발생, run_simulation()이 수만~수십만
스텝 도는 동안 노출 시간이 김). "지금 당장은 기능 비활성화"도
대안으로 제시했으나, 사용자가 근본 해결(로컬 변수화)로 진행 요청.

[ 해결 - 설계 ]
`Configs/Vehicle_Params.py`에 `build_default_cfg()` 팩토리 함수 추가:
physics/solar/cell/pack/power/drive/race를 매번 **새 인스턴스**로
묶어서 `SimpleNamespace`로 반환(모듈 전역 싱글턴 인스턴스 생성 로직과
동일, pack.Cell = cell 참조 연결도 동일하게 재현). `simpara`는 다이얼로그가
안 건드리는 값이라 그대로 전역 유지(안전).

기존 `step`/`const` dict 패턴을 그대로 확장해서 활용 - `run_simulation()`
이 새 `cfg` 인자를 받아서 이 7개 설정 객체를 **지역 변수로 destructure**
한 뒤 기존 `const` 딕셔너리에 담아 하위 함수들에 전달. "함수 맨 위에서
`physics = const["physics"]`처럼 한 줄만 추가하면, 그 아래 본문의 기존
`physics.X` 참조는 전부 그 지역변수를 가리키게 됨"이라는 점을 활용해서,
함수 본문 내부 로직은 거의 안 건드리고 시그니처+destructure 줄만
추가하는 식으로 손대는 범위를 최소화함.

[ 구현 ]
- Configs/Vehicle_Params.py: build_default_cfg() 추가.
- Functions/Vehicle_Function.py: cal_drive_res, gen_solar, update_soc,
  cs_stop_time_cal, cs_stop_simulation, compute_required_pace,
  compute_motor_derating, control_stop_handler, compute_vehicle_energy
  에 const 파라미터 추가(또는 이미 있던 const에 설정값 destructure
  추가 - compute_lookahead). run_simulation()은 신규 cfg 파라미터를
  받아 지역변수로 풀고, const 딕셔너리 생성부에 physics~race 7개를
  추가, 모든 하위 호출부(compute_required_pace/compute_motor_derating/
  control_stop_handler/compute_vehicle_energy/mpc_speed)에 const 전달
  하도록 수정.
- mpc/mpc_controller.py: mpc_speed(step, params, const)로 변경,
  solar/pack/race/drive를 const에서 꺼내 씀(simpara는 계속 전역).
- scripts/main.py: build_default_cfg()로 cfg 생성 후 run_simulation()
  호출부 2곳에 전달(단일 프로세스 CLI 스크립트라 세션 개념은 없지만
  시그니처 요구사항 맞추기 위함).
- app.py: "차량 제원 설정" 다이얼로그가 전역 physics 등 대신
  `st.session_state.cfg`(세션 진입 시 build_default_cfg()로 1회 생성)
  를 읽고 씀. run_simulation() 호출부와 결과 화면의 race.Control_Stop_2025
  /race.total_distance 참조도 전부 st.session_state.cfg.race로 교체.

[ 검증 ]
스크래치패드 테스트 스크립트로 확인:
- cfg_b.physics.mass를 250 -> 500으로 변경.
- cfg_a.physics.mass는 그대로 250 유지 (영향 없음, unaffected=True).
- 모듈 전역 physics.mass도 그대로 250 유지 (영향 없음, unaffected=True).
- mass가 다르니 실제 시뮬레이션 결과도 다름(평균속도 76.6 vs
  70.3 km/h) - cfg가 죽은 파라미터가 아니라 실제로 반영됨을 함께 확인.
py_compile로 5개 수정 파일 전부 문법 검증, 로컬 Streamlit 서버 정상
기동 확인.

요청해서 Vehicle_Function.py/mpc_controller.py를 Claude가 직접 수정.
