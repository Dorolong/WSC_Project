================================================================
파일별 현재 상태: mpc/mpc_controller.py
================================================================

[ 역할 ]
Rule-based MPC 속도 플래너. mpc_speed() 하나의 함수가 매 스텝 호출되어
현재 상태(SOC, 경사, 일사량, 풍향 등)로부터 권장 속도를 계산.

[ 함수 시그니처 ]
mpc_speed(step, params)
- **이름 변경(2026-07-20)**: 이전엔 mpc_speed(state, params)였으나,
  Functions/Vehicle_Function.py의 run_simulation()이 이제 별도
  state dict를 만들지 않고 step을 그대로 전달하는 구조로 정착돼서,
  파라미터명도 실제 넘어오는 값과 일치하도록 state -> step으로
  일괄 변경(본문 내 참조 21곳 전부 포함). 동작 변화는 없음, 순수
  명명 일관성 정리.
- step은 필수 데이터(매 스텝 항상 존재해야 함)라 step["key"]로
  바로 인덱싱(기본값 없이, 누락 시 KeyError로 즉시 드러나야 함).
  params는 튜닝 계수라 기존처럼 params.get(key, default) 유지.
- step 생성은 Functions/Vehicle_Function.py의 run_simulation()
  루프 안에서 매 스텝 이루어짐(이 파일엔 별도 스키마 선언 없음).

[ 현재 로직 순서 ]
1. LV1 - SOC 기반 속도(ramp): frac = clip((soc-soc_ramp_low)/
   (soc_ramp_high-soc_ramp_low), 0, 1); v = v_min + frac*(v_soc_high
   - v_min).
2. **LV2 - 경사각 보정(ramp) + momentum 결합(2026-07-20 신규)**:
       slope_severity = clip((step["slope_ahead"] - 0.02) / 0.02, 0, 1)
       momentum = clip(step["a"] * momentum_gain, 0, 1) * slope_severity
       v -= slope_k * step["slope_ahead"] * (1 - momentum)
   기존엔 v -= slope_k * slope_ahead 단순 비례식이었는데, simpara.a가
   고정 상수에서 실측 기반 동적값(cal_drive_res에서 (v-prev_v)/dt로
   계산)으로 바뀌면서 momentum(직전 가속도)이 오르막 페널티를
   완화하도록 결합. slope_severity로 "확실한 오르막(slope_ahead>0.02
   근방)"에서만 momentum 효과가 스무스하게 켜지도록 게이팅 -
   하드 if 대신 램프를 쓴 이유는 LV8 하드스위치 경계값 버그 이력
   때문(과거 debug_log 참고). 물리적 타당성(회생제동 효율 0.6으로
   인한 손실 감안 시 "가속 후 회생" 형태는 오히려 손해, "회생 없는
   자연 가감속"만 실질적 이득)은
   debug_logs/(2026-07-20)_simpara_a_동적화_및_LV2_momentum_결합.txt
   참고. **실제 SOC 개선 효과는 아직 A/B 검증 안 됨.**
3. LV3 - 일사량 비율 보정(ramp, 게이트 없음): gen_ratio_conservation
   = gen_ratio - radi_risk * gen_ratio_std; v += (gen_ratio_conservation
   - 0.5) * radi_para.
4. LV4 - 에너지 예산 보정(ramp, 구 LV7 병합): avg_gen_ratio로 향후
   발전량 추정 -> expected_soc_per_km 산출 -> energy_crit =
   (soc_start_min - soc_cutoff) / leg_dist_km -> deficit =
   clip((energy_crit - expected_soc_per_km)/energy_crit, 0, 1) ->
   v -= deficit * energy_v.
5. LV5 - 정면풍 보정(ramp): v -= clip(winddir_para*headwind,
   -winddir_para, winddir_para).
6. v 하한 클램프: v = max(v, v_min). 누적 보정으로 v가 0 이하까지
   내려갈 수 있어 다음 나눗셈에서 divide-by-zero 방지.
7. SOC 하한 하드컷: soc <= soc_cutoff면 그냥 v_min으로 고정(의도적
   하드 세이프티, ramp 대상 아님).
8. LV8(2개 페이스 신호 3항 가중평균): soc_cutoff 초과 시에만 작동.
   - 전체 완주 기준: urgency_total * soc_factor_total(margin_total)
   - 다음 CS 기준: urgency_next_cs * soc_factor_next_cs(margin_next_cs)
   - v = (v + global_factor*required_race_pace +
          next_cs_factor*required_next_cs_pace) / (1+global_factor+
          next_cs_factor)
9. 물리적 상한 클리핑: 전압 디레이팅(v_max_derated), 최종 v_min/
   drive.v_max
9.5. **법정 최고속도 클립 (신규, 2026-07-20)**: v = min(v,
   step["speed_limit"]). **순서가 중요** - 반드시 v_min 하한
   클램프/drive.v_max 클립보다 뒤에 와야 함. 안 그러면 v_min
   강제 로직(예: 60)이 그보다 낮은 법정 속도제한(예: CS 진입
   25km/h)을 무시하고 덮어쓰는 버그가 남. step["speed_limit"]은
   Vehicle_Function.py의 compute_speed_limit()에서 미리 계산돼
   step에 실려옴(mpc_controller.py는 원시 데이터 조회 안 하고
   클립만 적용 - 아키텍처 원칙, progress/22 참고).
10. 스텝 변화량 제한 - 댐퍼(EMA+tanh):
    delta = v - step["prev_v"]
    v = step["prev_v"] + simpara.max_v_delta * tanh(alpha * delta / simpara.max_v_delta)

[ mpc_default_params 현재 키 목록 ]
v_soc_high, soc_ramp_high, soc_ramp_low, slope_k, **momentum_gain
(신규, 기본 1.0)**, radi_para, radi_risk, energy_v, winddir_para,
margin_total, margin_next_cs, soc_cutoff, v_min, alpha
- momentum_gain은 LV2의 momentum 결합식에서 step["a"]에 곱해지는
  계수. Optuna 탐색공간(scripts/main.py)에는 아직 미포함(고정값).
- 나머지 키는 이전 세션(07-17/07-18)에 확정된 이름 그대로 유지.
- scripts/main.py의 탐색공간과 반드시 이름이 일치해야 함(세 지점
  - 딕셔너리, mpc_speed() 본문, main.py suggest 호출부 - 중 하나라도
  다르면 조용히 기본값 fallback되는 위험). momentum_gain을 나중에
  탐색공간에 넣을 경우 이 세 지점 동기화 잊지 말 것.

[ 상태 ]
LV1~LV5 전부 ramp 방식(하드 세이프티 2곳만 계단형 유지: soc_cutoff,
soc_hard_stop). LV2에 momentum(step["a"]) 결합 완료. 함수 시그니처
state->step 이름 통일 완료. 법정 속도제한 클립 추가 완료(순서
검증됨). 이 구성으로 Optuna 트라이얼이 에러 없이 도는 것까지
확인, control_stop_handler 리팩터링 A/B 검증도 완료(progress/19).
momentum 결합의 실제 SOC 개선 효과 및 파라미터 재탐색은 아직 진행
전(CS 코스팅/제동, 내리막 세그먼트 캡 등 나머지 설계 반영 후로
의도적 보류 - progress/22 참고). 오르막 처리는 momentum_gain 방식
유지, 향후 비용함수 MPC 전환 시 배터리 I²R 손실 기반 명시적 비용항
으로 재설계 예정(momentum_gain을 세그먼트 방식으로 바꾸는 게 아님).
