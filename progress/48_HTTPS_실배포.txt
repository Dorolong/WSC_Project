[ 구현 ]
1. IP 고정: ephemeral -> reserved 전환.
   141.147.167.152 -> **161.33.149.239**
   ephemeral 은 reserved 로 "변환"이 안 되고 떼었다 붙이는 방식이라
   주소가 새로 발급된다. 콘솔 Edit 에서 Reserved 선택지가 안 보이면
   먼저 "No Public IP" 로 ephemeral 을 떼야 나타난다.
2. 도메인: wsc-drive.duckdns.org (DuckDNS 무료).
   DuckDNS 를 고른 이유는 Public Suffix List 등재로 Let's Encrypt
   발급 한도 버킷이 서브도메인마다 독립이기 때문. nip.io/sslip.io 는
   전 세계가 한도를 공유해서 부적합.
3. 방화벽 2겹: 오라클 Security List(콘솔) + 서버 iptables.
   80/443 개방, 8000 제거, netfilter-persistent save.
4. Caddy v2.11.4 설치 + server/Caddyfile 배치.
   Let's Encrypt 인증서 자동 발급(tls-alpn-01)/자동 갱신.
   보안 헤더 4종 + CSP + Server 헤더 제거.
5. uvicorn 을 --host 127.0.0.1 로 전환(+ --proxy-headers
   --forwarded-allow-ips 127.0.0.1). 프록시 뒤에만 노출.
6. DuckDNS keep-alive cron 등록(17 4 * * *).
   IP 는 고정이지만 **갱신 요청이 오래 없으면 DuckDNS 가 도메인을
   정리**하므로 살려두는 용도. IP 고정과 도메인 유지는 별개 문제다.

[ 검증 (외부 실측) ]
  port 80 열림 / 443 열림 / **8000 닫힘**
  https 200, http 는 308 리다이렉트
  보안 헤더 4종 적용, Server 헤더 없음
  uvicorn 바인딩 127.0.0.1:8000
  서비스 4개(caddy, wsc-launcher, netfilter-persistent, cron)
    전부 enabled + active -> 재부팅 생존
  /etc/iptables/rules.v4 에 22/80/443 만 존재(8000 없음)

[ 배포 중 발견하고 고친 버그 3건 ]

(1) 요청 로그에 client IP 가 없었다 (검증 V-7 실패)
    원인은 프록시 설정이 아니라, server/main.py 의 log_requests
    미들웨어가 method/path/status/소요시간만 남기고 접속자를 아예
    안 찍고 있었던 것. client 를 첫 필드로 추가.
    -> 113.198.219.89 GET /api/status 200 1.4ms

(2) optuna_runs 조회가 401
    "내 기록"에서만 발생. CSP 문제가 아니었다(요청이 Supabase 까지
    도달했다). 테이블에 authenticated 역할 GRANT 가 없었던 것.
    **RLS 정책이 없으면 빈 배열 200 이 오지만, 테이블 GRANT 가
    없으면 401 이 온다 - 증상이 다르니 원인 추적에 쓸 수 있다.**
    SETUP.md 에 create table + grant + RLS 정책 전체를 정리했다.

(3) access token 만료로 API 가 401 (2단계로 드러났다)
    a) state.js 가 로그인 시점의 토큰을 한 번만 붙잡아두고 계속
       재사용했다. Supabase 토큰은 기본 1시간이면 만료되고
       supabase-js 가 백그라운드 갱신을 해도 이 모듈 변수에는
       반영되지 않는다. 페이지를 오래 열어두면 이후 모든 호출이
       401 이 되고 진행률 폴링이 죽는다.
       단서는 **폴링이 연속 401 을 낸 것**이었다(07:26:39~43).
       일회성 경합이면 그런 모양이 안 나온다.
       -> apiHeaders() 를 async 로 바꿔 매 호출마다 현재 세션에서
          토큰을 다시 받도록. 호출부 7곳에 await 추가.
          state.js 가 auth.js 를 import 하면 순환 참조라
          setTokenProvider() 주입 방식으로 뒀다.
    b) 그래도 **페이지 로드당 정확히 1회** 401 이 남았다.
       localStorage 에 남아있던 세션이 이미 만료됐어도 getSession()
       은 그 만료된 토큰을 그대로 돌려주고, 자동 갱신은 조금 뒤에야
       돌기 때문. 401 응답이 290ms 걸린 것도 서버가 실제로 Supabase
       에 물어보고 거절당했다는 뜻이라 이 해석과 맞았다.
       -> expires_at 을 보고 이미 지났거나 60초 내 만료면
          refreshSession() 으로 직접 갱신. 여유가 있으면 저장된
          토큰을 그대로 쓰므로 네트워크 호출은 안 늘어난다.

[ 그 외 ]
- 콘솔 404 는 전부 /favicon.ico 였다. data: URI 파비콘을 head 에
  넣어 요청 자체를 제거(CSP img-src 에 data: 허용돼 있음).
- HSTS 는 1일로 시작해 검증 통과 후 **1주일(604800)** 로 올렸다.
  max-age 는 만료 날짜가 아니라 **슬라이딩 윈도**다 - 방문할 때마다
  타이머가 그 시점부터 새로 시작되므로 "마지막 방문 후 N초간 기억"
  이라는 뜻이다. 몇 주 안정적이면 1년으로 올릴 것.
  preload 는 붙이지 않았다(빼는 데 수개월 걸림).
- 로그에 /actuator/health 같은 **자동 스캐너 probe** 가 잡혔다.
  공개 IP 라 정상적인 현상이고, 이런 게 보인다는 것 자체가
  Phase 0 로깅의 값어치다.
