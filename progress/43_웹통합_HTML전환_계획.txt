[ 배경 - 왜 전환하는가 ]
사용자가 Streamlit UI를 HTML/CSS/JS로 바꾸고 싶다고 요청. 이유 3가지를
직접 밝혔고, 결정력 순서는 아래와 같다.

1. **다른 HTML 기반 웹과 합칠 예정 (결정적)**
   Streamlit을 외부 사이트에 넣는 방법은 iframe 하나뿐이다. 그러면
   스크롤이 따로 놀고, 상위 사이트의 네비게이션/폰트/색을 공유하지
   못하고, 딥링크도 안 된다. 이건 취향이 아니라 통합 제약이라
   나머지 두 이유가 없어도 혼자서 전환을 정당화한다.
2. **UI 시인성 향상**
   유효하지만 기술이 아니라 설계가 만드는 차이다. 정확히 말하면
   "Streamlit이 씌우는 천장이 사라지는 것"이다. 셋 중 혼자서는
   제일 약한 근거.
3. **진짜 서버 구축 - 로그 남기기**
   유효하고 이미 구체적인 구멍이 있다(아래 Phase 0 참고). 다만
   로그 자체는 Streamlit을 버려야만 되는 건 아니다. 진짜 이득은
   이미 uvicorn+systemd로 도는 구조라 journald에 자연스럽게 쌓이고,
   요청 단위 로그(누가/언제/어떤 파라미터로)가 의미를 갖는다는 점.

[ 방침 - Streamlit 병행 (사용자 결정 2026-08-05) ]
**"동일한 UI 개선을 양쪽에 병행 적용"으로 확정.**
새 HTML 프론트에 넣는 변경(로그인 게이트 선배치, 시인성 개선 등)을
Streamlit 앱에도 같은 단계에서 반영한다. 작업량은 2배지만 전환
완료 전까지 팀원 사용 경험이 안 깨진다.
-> 아래 각 Phase에 **[A] 새 HTML** / **[B] Streamlit** 두 트랙을
   같이 적어뒀다. 한 Phase를 끝낼 때 두 트랙을 같이 끝낼 것.

[ 핵심 설계 결정 3가지 ]
================================================================
1. **시뮬레이션 실행 = 서브프로세스 + 진행률 파일**
   study_runner.py가 이미 쓰는 패턴을 그대로 복제한다. 스레드보다
   나은 이유: 크래시가 서버를 안 죽이고, 진행률 폴링 코드를 Optuna와
   공유할 수 있다.

2. **run_simulation() / mpc_speed()는 건드리지 않는다**
   현재 시그니처가 이미 cfg를 인자로 받고 (df, reason)을 반환하는
   형태라 그대로 호출하면 된다(app.py:761 참고).
   **CLAUDE.md 규칙: Functions/Vehicle_Function.py와
   mpc/mpc_controller.py는 사용자가 직접 작성. Claude는 이 두 파일에
   Edit/Write 하지 않는다.** 이번 작업은 인프라/배관이라 그 두 파일을
   수정할 이유가 없어야 정상이다 - 수정이 필요해지면 그건 설계가
   잘못됐다는 신호.

[ 미리 짚어둘 문제 ]
================================================================
1. **레이아웃 폭 충돌**
   server/static/index.html:29 - .wrap { max-width: 480px }.
   현재 Optuna 페이지는 모바일 우선 좁은 레이아웃인데, 시뮬레이터는
   5단 차트라 넓은 화면이 필요하다(Streamlit도 layout="wide").
   셸 설계 때 뷰별 폭 규칙을 먼저 정할 것.
   **시인성이 목표라면 여기가 실제 승부처다.**

2. **[확정 2026-08-05] 배포는 오라클 단일화**
   Streamlit Cloud를 접고 오라클 서버 하나로 간다. 이때 시뮬레이션
   CPU 부하가 오라클로 넘어온다.
   **주의: 현재 MAX_CONCURRENT=1은 Optuna 탐색 기준으로 잡힌 값이다.**
   시뮬레이션은 수십 초~수 분, Optuna는 훨씬 길어서 성격이 다르므로
   같은 예산을 나눠 쓰게 하면 안 된다.
   -> **별도 슬롯으로 분리할 것**: WSC_MAX_SIM_CONCURRENT (기본 2 정도)
      를 신설하고, 시뮬레이션 큐와 Optuna 큐를 따로 관리.
      _active_count()도 종류별로 세도록 수정 필요.

3. **CORS - [해소됨] same-origin이라 비이슈**
   합칠 웹이 오라클 서버와 **같은 도메인**으로 확정(2026-08-05).
   프론트와 API가 같은 출처이므로 CORS 프리플라이트가 아예 안 뜬다.
   -> server/main.py의 allow_origins=["*"]는 **좁히거나 제거**할 것.
      지금 상태는 아무 사이트나 이 API를 호출할 수 있다는 뜻이라
      불필요하게 열려 있다(백로그 3순위 4번).
   -> Supabase anon key 하드코딩은 별개 항목. RLS 전제하에 공개돼도
      되는 값이라 당장 위험하진 않으나 노출 범위는 계속 추적.

4. **서버 재시작 시 진행 중 상태 소실**
   RUNS/QUEUE가 메모리 전용. 시뮬레이션 실행도 같은 구조로 가면
   같은 한계를 물려받는다. 완료 결과는 파일+Supabase에 남으므로
   치명적이진 않으나, 시뮬레이션은 Optuna보다 짧아서 영향은 더 작음.

[ 확정된 저장/보존 정책 (2026-08-05 사용자 결정) ]
================================================================
**대전제: 사용자별로 영구 보관하는 것은 "요약"만이다.**
사용자가 "각각의 사용자가 best parameter 형태로 1GB까지"로 답했고,
확인 결과 대상은 **best_params + 지표 요약**이다.

실측한 크기 (2026-08-05, 로컬 outputs/ 기준):
  best_params JSON        1KB 미만/건   <- 영구 보관 대상
  시뮬레이션 결과 CSV     **13MB/건**   <- 경로 포인트 151,933개
  Optuna study db         120KB/건
  env_data.csv            3.9MB (고정)
  Optuna_result.csv       23MB (로컬 누적 산출물)

**핵심: 1GB 상한은 요약본 기준으로는 사실상 도달 불가능하다.**
1KB × 100만 건이 돼야 1GB다. 즉 이 상한은 안전장치일 뿐 실제
운영을 제약하지 않는다. **반대로 진짜 디스크를 위협하는 건 시뮬레이션
결과 CSV(13MB/건)이며, 이건 영구 보관 대상이 아니다.**

디스크 전제: 오라클 무료 티어 부트 볼륨 기본값 ~47GB.
(OS+.venv 등 제하고 실여유 30GB대 예상 - 배포 후 df -h로 실측할 것)

정책 3분류:
 1. **요약 (영구)** - best_params, 최종 SOC, 도달거리, 종료사유 등
    -> 이미 Supabase(optuna_runs, simulation_runs)에 저장 중.
       서버 디스크에는 outputs/study_results/*.json만 남음(1KB급).
       **추가 설계 거의 불필요.** 사용자당 1GB 상한만 명목상 설정.
 2. **시뮬레이션 결과 CSV (임시)** - 13MB/건
    -> **다운로드 목적으로만 생성하고 TTL로 삭제.**
       권장: 사용자당 최근 5건 + 24시간 TTL.
       10명 × 5건 × 13MB = 650MB 로 상한이 잡힘.
       절대 무기한 쌓지 말 것 - 사용자당 77건이면 1GB다.
 3. **서버 운영 로그 (요청/에러/실행이력)**
    -> 사용자별로 나누지 말고 **서버 전체 한 덩어리로 총량 상한.**
       RotatingFileHandler(maxBytes=20MB, backupCount=10) = 총 200MB면
       충분. Phase 0에서 구현.

기존 가드와의 관계:
  server/study_runner.py:48 MIN_FREE_BYTES = 500MB (환경변수
  WSC_MIN_FREE_BYTES로 조절). 여유가 이 밑으로 떨어지면 study 파일을
  지우고 이어가는 로테이션이 이미 구현돼 있다.
  **위 2·3번 상한(총 ~1GB 미만)은 이 가드와 충돌하지 않는다.**
  단 시뮬 CSV TTL을 안 걸면 금방 충돌하므로 TTL은 필수.
