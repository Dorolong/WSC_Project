[ 1. app.py 결과 그래프 - 주제별 탭 분리 아이디어 ]
현재 app.py는 SOC/전력(소비+발전)/속도를 make_subplots로 3행짜리
그림 하나에 쌓아서 보여줌. 사용자 아이디어: 발전량/소비량/SOC/속도
등을 엑셀 시트 탭처럼 주제별로 나눠서 보여줄 수 있는지 문의.

결론: 가능함. app.py의 vehicle_settings_dialog()에서 이미
st.tabs(["물리 제원", "태양광 패널", ...]) 패턴을 쓰고 있으므로
(42~44번째 줄), 결과 그래프 쪽에도 동일 패턴 적용 가능:
    tab_gen, tab_cons, tab_soc, tab_speed = st.tabs([...])
    with tab_gen: st.plotly_chart(fig_gen, ...)
탭으로 나누면 주제별로 더 큰 화면에 자세한 그래프를 넣기도 쉬워짐
(예: 발전량 탭에 시간대별 분포 그래프 추가 등).

상태: 미착수, 아이디어 단계. 착수 시 app.py의 그래프 생성 블록
(현재 make_subplots 부분)을 tab별로 분리하는 작업 필요.

[ 2. 실시간 배포 아키텍처 - 고정계수 vs 가변 입력 ]
사용자 문제 제기: 예측 모델을 만드는 목적이 "고정된 파라미터로 모델을
확정"하는 게 아니라, 실시간 날씨를 받아서 N시간 앞을 예측하고 완주여부+
추천속도를 내는 것이어야 하지 않냐는 질문. 계수 자체가 variable해야
하는 것 아니냐는 문제의식.

정리된 답: mpc_speed()는 이미 상태 없는(stateless) 순수 함수라
매 호출마다 새 입력(SOC, 일사량, 필요 페이스 등)에 반응해서 다른
속도를 냄 - 입력은 이미 실시간/가변적. 고정되어 있는 건 그 입력을
얼마나 강하게 반영할지 정하는 ~16개 계수(LV1_V1, margin_total 등)뿐이고,
이는 머신러닝의 "학습된 가중치"와 같은 개념. 여러 날씨(K=5 등)에서
학습시켜 계수 자체를 일반화하는 것과, 그 계수가 받는 입력의 질을
실시간 예보(AI 예측 모델)로 높이는 것은 서로 다른 두 축이며 상호
보완적:
  - 계수를 강건하게(로버스트하게) 만드는 것 = 지금 하고 있는 K=5 탐색
  - 입력을 실시간화하는 것 = README 로드맵의 "AI 예측 모델로 MPC 입력
    고도화" 단계, 아직 미착수
계수 자체를 실시간으로 재튜닝(라이브 재최적화)할 필요는 없다고 결론.

[ 3. LV1~LV8 보정 방식의 step vs ramp 불일치 ]
관찰: LV1(SOC 3단계)/LV2(경사)/LV4(에너지)/LV6-7(추세)은 임계값을
넘으면 고정폭만큼 훅 점프하는 계단형(step), LV3(일사량)/LV5(풍향)/
LV8(블렌딩)은 clip 기반 연속 비례형(ramp). 계단형은 경계값 근처에서
목표속도가 불연속적으로 튀는 문제가 있음(v_rate_limiting이 실제 변화는
완화해주지만 목표 자체는 계속 널뜀).

제안된 변환 패턴 (LV3/LV5/LV8과 동일한 clip 기반 스타일로 통일):
  LV1: frac = clip((soc-soc2)/(soc1-soc2), 0, 1); v = v_min + frac*(V1-v_min)
  LV4: deficit = clip((energy_crit-expected)/energy_crit, 0, 1); v -= deficit*energy_v
  LV2, LV6-7도 동일한 방식으로 임계값 근처를 완만하게 처리 가능.

상태: 미착수. 착수하면 거동이 꽤 달라져서 지금까지 쌓인 탐색 이력과
다시 비교가 안 맞을 가능성이 높음 -> 착수 시 새 db로 전환 예정
(progress/08_mpc_controller.txt에도 동일 메모 있음).
