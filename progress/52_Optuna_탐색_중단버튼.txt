================================================================
Optuna 탐색 중단(Stop) 버튼 구현 (2026-08-05)
================================================================

[ 배경 ]
사용자가 "내가 돌린 trial을 중간에 중단하고, 그만큼을 저장하는 버튼"을
요청했다. 프로세스를 즉시 kill 하면 진행 중 trial 과 CHECKPOINT_EVERY
경계 이후 trial 이 사라질 수 있으므로, docs/codex_stop_run_task.txt 의
지시대로 Optuna study.stop() 기반 협조적 중단을 구현했다.

[ 구현 ]
- server/main.py
  - POST /api/runs/{run_id}/cancel 추가.
  - queued 런은 큐에서 제거하고 즉시 status="stopped".
  - running 런은 outputs/study_results/{study_name}.cancel 플래그를 만들고
    status="stopping" 으로 전환.
  - TERMINAL_STATUSES 에 stopped 추가, stopping 은 비종료 상태로 유지.
  - cancel_requested_at 을 runs_state.json 스냅샷에 포함.
  - WSC_CANCEL_GRACE_SECONDS(기본 300초) 이후에도 안 멈추면 terminate/kill.
  - stopping 도 동시 실행 슬롯을 차지하도록 _active_count() 보정.
- server/study_runner.py
  - 매 trial callback 에서 cancel flag 를 확인하고 study.stop() 호출.
  - completed += chunk 버그 수정: 실제 study.trials 의 finished 수 기반으로 계산.
  - 중단 시 status="stopped" 로 checkpoint/result JSON 저장.
  - best_params 가 있으면 중단 시에도 최종 단일 시뮬레이션 실행.
  - best_params 가 없으면 best_value/best_params 를 null 로 저장.
  - cancel flag 와 sqlite/-wal/-shm 파일 정리.
- server/static/index.html, server/static/js/optuna.js
  - My Search 카드에 Stop 버튼 추가.
  - queued/running/stopping 상태에서만 버튼 표시, stopping 에서는 disabled.
  - stopped 결과 카드 표시, best_value null 일 때 "-" 표시.
- server/static/js/auxiliary.js, app.py
  - stopped/stopping/interrupted/lost 상태 라벨 매핑 추가.
- app.py, server/static/data/release-notes.json
  - v1.2.0 릴리즈 노트 추가.
- server/README.md, server/wsc-launcher.service
  - WSC_CANCEL_GRACE_SECONDS 운영 변수 문서화.

- V-b completed 정확도: 코드 수정 완료, 실제 실행 검증 못 함.
- V-c queued 상태 Stop: 코드 경로 구현, 실제 실행 검증 못 함.
