[ 슬라이더 제거 -> Optuna 결과 읽기 전용 표시 ]
문제: 사이드바에 있던 11개 MPC 파라미터 슬라이더가 실제 워크플로우
(Optuna가 탐색하고 그 결과를 그냥 씀)와 안 맞고, 백엔드 파라미터 구조가
바뀔 때마다 슬라이더도 같이 손봐야 하는 유지보수 부담이었음 (실제로
LV1_V3 제거 때 동기화 안 돼서 KeyError 나는 버그 발생했었음).
-> 슬라이더 전부 삭제, 사이드바는 best_params를 표로 읽기 전용 표시.
"시뮬레이션 실행"은 best_params를 그대로 사용.

[ 레이아웃 정리 ]
- "차량 제원 설정" 버튼을 제목 옆(우측 상단)으로 이동 (st.columns).
  Streamlit 네이티브 Stop 컨트롤 근처에 배치하려는 의도.
- 차량 제원 다이얼로그를 세로로 길게 나열하던 것 -> st.tabs()로 8개
  카테고리(물리제원/태양광패널/배터리셀/배터리팩/전력시스템/구동계/
  레이스설정/OCV테이블) 분리.

[ 경로 지도 시각화 (가장 많은 시행착오) ]
목표: "호주를 가로지르는" 진행 상황을 시각적으로 보여주기.

1차: Plotly Scattermapbox(실제 지도 타일) - 시뮬레이션 진행에 맞춰
반복 갱신하려 했으나 매번 지도 타일이 새로 로드되면서 심하게 깜빡임.

2차: Scattermapbox -> 좌표 기반 Scatter(위경도를 그냥 x/y로 사용)로
전환해서 타일 로딩 자체를 없앰. 여전히 반복 호출 시 깜빡임 지속 확인
-> Streamlit이 st.plotly_chart를 반복 호출할 때마다 컴포넌트를 새로
마운트하는 게 근본 원인으로 파악.

3차: 커스텀 Streamlit 컴포넌트(components/route_animator/) 도입 결정.
Node.js 없이 순수 HTML/JS로 구현 (declare_component path=로 정적 파일
서빙). 디버깅 과정에서 발견한 버그들:
  - CDN(streamlit-component-lib.js) 로드 실패로 Streamlit 객체 undefined
    -> postMessage 프로토콜 직접 구현으로 외부 의존성 제거
  - 컴포넌트를 콜백 안에서 반복 호출 -> 매번 iframe 재생성돼서 화면이
    떴다 사라지길 반복 (근본적으로 Streamlit 컴포넌트는 "한 실행 내
    반복 갱신" 용도가 아님을 확인)
  - 수신 메시지에 isStreamlitMessage 플래그를 잘못 요구해서 실제
    render 메시지를 다 무시하고 있던 버그 (공식 소스 직접 확인 후 수정:
    그 플래그는 컴포넌트->호스트 방향에만 붙는 것)
  - 빨간 마커를 별도 <div>로 만들어 독립적으로 좌표 스케일링하다가
    SVG의 preserveAspectRatio 레터박싱과 안 맞아 경로에서 이탈하는 버그
    -> 마커를 SVG <circle> 대신 아예 제거, 오렌지색 경로선의 끝을
    현재 위치로 삼는 방식으로 단순화 (좌표계 불일치 문제 자체를 제거)

최종 구조: 컴포넌트를 실행당 딱 2번만 호출
  1) 시작 시: 배경(호주 실루엣 + 전체 경로) 1회 표시 + 6초 주기로
     반복 재생되는 장식용 애니메이션 시작 (실제 계산 진행률과 무관,
     경로 다 채우면 1초 홀드 후 재시작)
  2) 계산 완료 시: 애니메이션 없이 실제 도달 지점까지 즉시 스냅
     (완주 실패면 그 지점에서 멈춘 것처럼 보임)
실제 진행률은 애니메이션과 분리해서 st.markdown 텍스트(2배 크기, 볼드)로
표시, 그 아래 경과시간 기반 예상 남은 시간(Estimated Time Left)도 계산해서
표시. 텍스트 요소는 반복 갱신해도 깜빡임 없음 (커스텀 컴포넌트만 그 문제가
있었던 것).

[ 호주 실루엣 배경 이미지 ]
Google Maps 스크린샷은 저작권 문제로 사용 보류(구글 이용약관상 캡쳐 후
재배포 소지 있음). 대신 Natural Earth(퍼블릭 도메인) 데이터를
geopandas로 받아 호주 육지 폴리곤만 필터링, matplotlib으로 반투명
실루엣 PNG 생성 (assets/australia_silhouette.png). 처음엔 정사각형
캔버스로 저장해서 실제 위경도 비율(약 1.42:1)과 안 맞아 찌그러짐 ->
캔버스 종횡비를 좌표 범위에 맞춰 재생성. 페이지 전체 배경으로 쓰다가
지도 컴포넌트 자체가 이미 호주 모양을 보여줘서 중복이라 판단, 지도
좌표에 정확히 맞춰 배치하는 방식으로 이전 (geopandas는 이미지 생성
1회용이라 requirements.txt엔 미포함).
