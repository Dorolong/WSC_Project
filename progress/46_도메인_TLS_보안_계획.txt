[ 배경 - 지금 무엇이 뚫려 있나 ]
================================================================
서버가 http://161.33.149.239:8000 로 **평문 HTTP + 생 IP**다.
리버스 프록시도 TLS도 없이 uvicorn이 0.0.0.0:8000 에 직접 물려 있다.

**실질적 위험은 로그인이 아니라 그 다음이다.**
Supabase 로그인 자체는 https://...supabase.co 로 가니 안전하다.
문제는 거기서 받은 access token 을 우리 서버에 보낼 때다:

    Authorization: Bearer eyJhbGc...      <- HTTP 평문

같은 네트워크(카페/학교 와이파이)에 있는 사람이 이 토큰을 그대로
주워서 **본인 계정으로 API를 호출**할 수 있다. 게다가 HTML/JS도
평문으로 내려가므로 중간에서 스크립트를 갈아끼우는 것도 가능하다.

사용자 결정 (2026-08-05):

  - TLS: **Caddy 리버스 프록시**

[ 도메인 선택 - DuckDNS 권장 ]
================================================================
무료 옵션 중 **DuckDNS**(https://www.duckdns.org)를 권장한다.
확정: wsc-drive.duckdns.org

**권장 이유 (중요):**
DuckDNS 는 Public Suffix List 에 등재돼 있어서, 서브도메인마다
Let's Encrypt **인증서 발급 rate limit 버킷이 독립**이다.

**nip.io / sslip.io 는 쓰지 말 것.** IP를 그대로 도메인처럼 쓰는
편의는 있지만(161.33.149.239.nip.io), PSL 등재 상태가 달라서
전 세계 사용자가 rate limit 을 공유하게 되는 구조다. 남이 많이
쓰는 날에 인증서 발급이 실패한다. 또 IP가 이름에 박혀 있어서
오라클 인스턴스 IP가 바뀌면 도메인 자체가 바뀐다.

**[완료] 오라클 IP를 reserved 로 전환함 (2026-08-05).**
IP: 141.147.167.152 -> **161.33.149.239** (이름 WSC_Project)
- ephemeral 은 reserved 로 "변환"이 안 된다. 떼고 새로 붙이는 방식이라
  **주소가 새로 발급된다.** 콘솔 Edit 화면에서 Reserved 선택지가 안 보이면,
  먼저 "No Public IP" 로 바꿔 ephemeral 을 떼야 선택지가 나타난다.
- 이제 인스턴스를 stop/start 해도 IP가 유지되므로 DuckDNS 갱신 cron 은
  필요 없다. (안 할 거였으면 cron 으로 IP 변경을 따라가게 해야 했음)
- 쓰지 않게 된 예약 IP가 남아 있으면 Networking -> Reserved Public IPs
  에서 삭제할 것 (미할당 예약 IP는 계정 상태에 따라 과금될 수 있음)

[ Step 2 - 방화벽 개방 (오라클은 2단계다) ]
================================================================
**함정: 오라클은 방화벽이 두 겹이다. 둘 다 열어야 한다.**
한쪽만 열고 "왜 접속이 안 되지" 하는 게 가장 흔한 실패다.

2-1. [오라클 콘솔] VCN -> Security Lists -> Ingress Rules
       80/tcp   개방 (Let's Encrypt HTTP-01 챌린지에 필요)
       443/tcp  개방
       8000/tcp **삭제** (Caddy 뒤로 숨길 것이므로)
2-2. [서버 안] Oracle Ubuntu 이미지는 iptables 가 기본적으로
     22 외를 막아둔다. 반드시 같이 열고 **영구 저장**할 것:
       sudo iptables -I INPUT 6 -m state --state NEW -p tcp --dport 80 -j ACCEPT
       sudo iptables -I INPUT 6 -m state --state NEW -p tcp --dport 443 -j ACCEPT
       sudo netfilter-persistent save
     (netfilter-persistent 를 안 하면 재부팅 후 원상복구된다)

[ Step 3 - Caddy 설치 및 구성 ]
================================================================
3-1. 설치 (공식 apt 저장소)
3-2. /etc/caddy/Caddyfile 을 레포의 server/Caddyfile 로 교체하거나 심볼릭 링크
3-3. sudo systemctl reload caddy
3-4. 확인: https://wsc-drive.duckdns.org 접속 -> 자물쇠 표시
     http:// 로 접속하면 자동으로 https 로 리다이렉트되는지도 확인

Caddyfile 초안 (server/Caddyfile 로 커밋):

    wsc-drive.duckdns.org {
        reverse_proxy 127.0.0.1:8000

        header {
            # HSTS - 처음엔 짧게. 아래 "함정" 참고
            Strict-Transport-Security "max-age=86400"
            X-Content-Type-Options "nosniff"
            X-Frame-Options "DENY"
            Referrer-Policy "strict-origin-when-cross-origin"
            Content-Security-Policy "default-src 'self'; script-src 'self' https://cdn.plot.ly https://esm.sh; connect-src 'self' https://esm.sh https://wijwbujsihhzzjzawfzp.supabase.co https://raw.githubusercontent.com; style-src 'self' 'unsafe-inline'; img-src 'self' data:; font-src 'self'; frame-ancestors 'none'; base-uri 'self'; form-action 'self'"
            -Server
        }
    }

  * 정적 파일도 FastAPI 가 StaticFiles 로 서빙하므로 reverse_proxy
    한 줄이면 된다. Caddy 에서 따로 file_server 를 두면 경로가
    이중 관리되니 하지 말 것.
  * Caddy 는 Let's Encrypt 인증서 발급/갱신을 자동으로 한다.
    certbot cron 같은 걸 따로 만들지 말 것.

[ Step 4 - 레포 변경 ] **완료 (2026-08-05)**
================================================================
실제로 적용된 것:
  - server/Caddyfile 신규 (도메인 wsc-drive.duckdns.org 박아넣음,
    CSP는 실측한 외부 출처 4곳만 허용, staging 발급 블록도 주석으로 포함)
  - server/wsc-launcher.service: --host 127.0.0.1 +
    --proxy-headers --forwarded-allow-ips 127.0.0.1
  - app.py:28 WSC_OPTUNA_SERVER_URL -> https://wsc-drive.duckdns.org
아래는 원래 지시 내용(참고용).

4-1. **server/wsc-launcher.service 를 127.0.0.1 바인딩으로 변경**
       ExecStart=... uvicorn server.main:app --host 127.0.0.1 --port 8000
     **--host 0.0.0.0 을 그대로 두면 Caddy 를 세워도 8000 포트로
     직접 들어오는 평문 경로가 남는다.** 방화벽에서 8000 을 막는
     것과 이중으로 막을 것.
     또한 프록시 뒤에 있으므로 --proxy-headers --forwarded-allow-ips 127.0.0.1
     를 붙여 클라이언트 IP가 로그에 제대로 남게 할 것.
4-2. server/Caddyfile 신규 커밋 (위 초안)
4-3. app.py 의 WSC_OPTUNA_SERVER_URL 을 https://wsc-drive.duckdns.org 로.
     (app.py 는 legacy 보관 중이지만 아직 살아있으므로 같이 고칠 것)
4-4. server/README.md 에 이 배포 절차 반영, SETUP.md 에서 링크
4-5. 로깅: --proxy-headers 적용 후 요청 로그의 client IP 가
     127.0.0.1 로만 찍히지 않는지 확인

[ 함정 모음 (미리 알고 갈 것) ]
================================================================
F-1. **오라클 방화벽 2겹** - Security List 만 열고 iptables 를
     안 열면 접속이 안 된다. 가장 흔한 실패. Step 2 참고.
F-2. **netfilter-persistent save 누락** - 재부팅하면 원복된다.
F-3. **uvicorn 0.0.0.0 방치** - Caddy 를 세워도 8000 평문 경로가
     살아있어서 HTTPS 강제가 무의미해진다. Step 4-1.
F-4. **CSP 로 앱이 조용히 깨진다** - cdn.plot.ly 나 esm.sh 를
     빠뜨리면 차트가 안 뜨거나 로그인이 안 되는데, 화면에는
     아무 에러도 안 보이고 콘솔에만 찍힌다. 적용 후 반드시
     브라우저 콘솔을 확인할 것.
     -> 처음엔 Content-Security-Policy-Report-Only 로 걸어서
        위반을 관찰한 뒤 강제로 전환하는 것도 방법.
F-5. **HSTS preload 를 처음부터 켜지 말 것** - preload 목록에
     한번 올라가면 빼는 데 수개월 걸린다. 도메인/구성이 확정되기
     전에는 preload 를 붙이지 않는다. max-age 도 짧게 시작.
F-6. **ephemeral IP** - 인스턴스 stop/start 로 IP가 바뀌면
     도메인이 엉뚱한 곳을 가리킨다. reserved IP 전환 권장.
F-7. **Let's Encrypt rate limit** - 설정을 반복 실패하며 재시도하면
     발급 한도에 걸린다. 구성 실험 중에는 Caddy 의 staging 발급
     (acme_ca 를 LE staging 으로) 을 쓰다가 마지막에 전환할 것.
