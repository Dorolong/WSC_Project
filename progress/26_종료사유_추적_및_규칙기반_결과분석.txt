[완료] 시뮬레이션 종료 사유 추적 + 규칙 기반 결과 분석 패널
================================================================
완료일: 2026-08-02

[ 배경 ]
"결과 분석을 AI로 해줄 수 있냐"는 질문에서 시작. Claude API 연동을
검토했으나(비용/구현 자체는 어렵지 않음), 다음 이유로 기각:
- API 사용량은 Claude.ai 구독/Claude Code 사용량과 완전히 별개의
  종량제(pay-as-you-go) 풀이라, 실제 현금이 나가는 구조임을 확인.
- 공개 앱(회원가입 개방)에서 다른 로그인 사용자가 분석을 누르면
  그것도 전부 앱 소유자 계정의 API 크레딧으로 청구됨 - 사용자별로
  자기 API 키를 넣게 하는 방식(BYOK)도 검토했으나, Claude.ai
  로그인으로 바로 위임되는 공식 OAuth가 없어 별도 개발자 계정 발급
  이 필요해 일반 방문자 진입장벽이 큼.
- 결론: AI 대신 **케이스별 분기 규칙 기반 분석**으로 방향 전환.

[ 문제: 종료 사유가 코드에 없었음 ]
run_simulation()이 df만 리턴하고 "왜 멈췄는지"는 안 넘겨줬음.
실제로는 각 break 지점에 이유가 이미 다 있었음(SOC 하한, CS 마감
초과, 구간평균속도 미달, 27일 초과) - 이걸 명시적으로 리턴하도록
수정.

[ 구현 - Functions/Vehicle_Function.py ]
사용자가 "둘 다(스펙+구현) 진행하도록 해"라고 명시적으로 요청해서
이번엔 예외적으로 Claude가 직접 작성(평소엔 사용자가 직접 작성하는
파일).
- calender_handler(): 27일 초과 "Stop" 리턴에 reason 추가
  ("27일 제한기간 초과").
- control_stop_handler(): 두 종류의 "Fail" 리턴에 각각 reason 추가
  (f"{CS이름} 마감시각 초과" / f"{CS이름} 구간 평균속도(60km/h) 미달"
  - CS 이름은 race.Control_Stop_2025[cs_hit]에서 가져옴, 어느 CS
  에서 실격났는지까지 표시됨).
- run_simulation(): termination_reason 변수 도입(기본값 "완주",
  break 3곳 - 27일초과/CS실격/SOC하한 - 에서 각각 덮어씀), 루프가
  break 없이 끝까지 돌면(i>=n) "완주"가 그대로 유지됨. 최종
  **return 값이 pd.DataFrame(results) 단독에서 (df, termination_reason)
  튜플로 변경** - 시그니처 변경이라 모든 호출부 수정 필요.

[ 호출부 수정 ]
- scripts/main.py: objective() 안 호출부 `df, _reason = ...`로 수정
  (reason 현재 미사용, 추후 스코어링에 활용 가능하도록 그대로 받아만
  둠). 최종 best_params 재실행 호출부는 `df, reason = ...` + reason
  출력(print) 추가.
- app.py: `df, reason = run_simulation(...)`로 수정, reason을
  session_state.last_reason에 저장(결과 화면이 session_state 기반
  으로 유지되는 구조라, progress/25에서 만든 last_df 패턴과 동일하게
  버튼 rerun에도 유지되도록).

[ 구현 - app.py 결과 분석 패널 ]
"완주 성공/실패" 지표 바로 아래 "결과 분석" 섹션 추가, reason
문자열의 부분 매치(in 연산자)로 분기:
- reason == "완주": 최저 SOC와 soc_hard_stop 마진이 5%p 미만이면
  "여유가 적었다" 경고, 아니면 "여유 있게 완주" 성공 메시지.
- "SOC" in reason: 배터리 소비 과다 추정, energy_v/soc_cutoff 조정
  제안.
- "마감시각" in reason: 전체 페이스 부족 추정, margin_total/
  margin_next_cs 확인 제안.
- "구간 평균속도" in reason: 해당 CS 구간 저속 주행 추정.
- "제한기간" in reason: 27일 초과 안내.
- 그 외: reason 그대로 표시(안전망).

[ 검증 ]
스크래치패드에 테스트 스크립트 작성해 run_simulation() 단독 호출로
(df, reason) 튜플 반환 확인 - 기본 mpc_default_params로는 27일
초과(termination_reason="27일 제한기간 초과")로 종료, rows=141692,
max_dist=2,833,560m 확인. py_compile로 3개 수정 파일(Vehicle_Function
.py, scripts/main.py, app.py) 문법 검증, 로컬 Streamlit 서버 정상
기동 확인.

의 objective()에서는 안 쓰고 있음(향후 필요시 실격 유형별 다른
페널티를 주는 스코어링 개선에 활용 가능 - 백로그에는 아직 미등록).
