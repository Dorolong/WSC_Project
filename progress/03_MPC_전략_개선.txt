MPC 전략 개선 (LV1 구조 정리 + LV8 신설 + 컨트롤스탑 규칙)
================================================================

[ LV1 파라미터 구조 정리 ]
문제: Optuna 탐색 구간이 LV1_V1(60-100)/V2(50-90)/V3(40-80)로 서로 겹쳐서
"SOC 낮을 때 오히려 더 빨리 감" 같은 전략적으로 말이 안 되는 조합까지
탐색 공간에 포함 -> 트라이얼 낭비.
1차 수정: 겹치지 않는 고정 구간(V1:70-100, V2:50-70, V3:0-50)으로 분리.
2차 발견: V3 최하위 티어랑 v_min(최종 하한선)이 사실상 같은 역할인데
따로 탐색되고 있어서 V3<v_min인 조합은 항상 v_min에 덮어써져 낭비.
-> LV1_V3 완전히 제거, 최하위 SOC 티어는 params["v_min"]을 그대로 사용.
3차 발견: 그러면 V2(50-70) vs v_min(20-60) 사이에 같은 겹침 문제 재발
가능성 -> 순차 샘플링으로 전환:
    v_min = suggest_int("v_min", 20, 60)
    LV1_V2 = suggest_int("LV1_V2", v_min, 100)
    LV1_V1 = suggest_int("LV1_V1", LV1_V2, 100)
이러면 범위를 어떻게 조정해도 구조적으로 v_min <= V2 <= V1이 항상 보장됨
(이런 종류의 순서 버그가 반복돼서 근본적으로 막은 것).

[ LV8: 시간 예산 기반 속도 조정 신설 ]
배경: 완주 실패 트라이얼들을 재실행해서 분석해보니, SOC가 충분히
남아있는데도(예: 58%) 일몰 무렵 LV3(일사량 보정)가 SOC 여유와 무관하게
항상 감속시켜서 v_min 근처로 눌린 채 "허용된 날짜"가 먼저 소진되는
패턴을 발견 (에너지 문제가 아니라 시간 문제).

1차 시도(하드 스위치): required_race_pace(남은거리/남은시간) 계산해서
LV8_soc_min 이상일 때만 v = max(v, required_race_pace * margin)로 강제.
-> 검증 중 심각한 버그 발견: required_race_pace가 레이스 시작부터
   이미 시속 67km/h대라, SOC 낮아서 보수적으로 가야 할 때도 LV8이
   억지로 속도를 끌어올려 오히려 24%밖에 못 가고 조기 실격 (원래
   59%보다 악화). LV8_soc_min을 LV1_soc2 기준으로 게이트해서 1차 완화.
2차 문제: 그래도 Optuna가 LV8_soc_min을 너무 높게(0.54) 잡은 트라이얼은
   결승선 근처 SOC 25%에서 LV8이 꺼져버려 같은 문제 재발 (경계값 어디서
   잡든 그 바로 아래서 문제가 생기는 구조적 한계로 판단).
3차 재설계(스무스 블렌드, 최종): 하드 스위치 제거, 연속 가중평균으로 전환:
    urgency = clip((required_race_pace - v) / v, 0, 1)
    soc_factor = clip((soc - soc_cutoff) / margin, 0, 1)
    v = (1 - urgency*soc_factor) * v + (urgency*soc_factor) * required_race_pace
15만 스텝에 걸쳐 매 스텝 작은 비율로 누적 작동하는 방식이라 급격한 전환
경계가 없음. LV8_time_margin, LV8_soc_min 파라미터 제거, margin(0.1-0.6)
하나로 통합.

[ 컨트롤스탑 규칙 (마감/오픈시간/구간 평균속도) - 현재 비활성화 상태 ]
RaceConfig에 CS_open_hour(CS별 오픈 시각), min_leg_avg_speed(구간 최소
평균속도 60km/h) 필드 신설. run_simulation()에 3가지 규칙 구현:
  1) day_end_dist 기준 마감 - 그날 목표 지점 못 넘으면 실격(break)
  2) CS 오픈 시간 전 도착 시 오픈 시각까지 대기 후 정차 시작
  3) 직전 CS ~ 현재 CS 구간 평균속도가 60km/h 미만이면 실격
검증: SOC 58% 남기고도 시간 마감으로 실격되던 것과 정확히 일치하는
"벌어치기" 패턴을 확인 (초반 3일 SOC 0.8+ 유지하다 막판에 몰아쓰는 전략).
현재 상태: best_params가 아직 이 규칙 기준으로 재탐색이 안 된 상태라
app.py에서 "완주 실패"로 잘못 표시되는 걸 막기 위해 3가지 로직 모두
Functions/Vehicle_Function.py에서 주석처리해 임시 비활성화함.
CS_open_hour는 지금 전부 8시 placeholder -> 실제 2025 대회 PDF 값으로
교체 예정.

[ 관련 파일 ]
mpc/mpc_controller.py, Functions/Vehicle_Function.py,
Configs/Vehicle_Params.py, scripts/main.py

[ 상태 ]
LV1 구조 정리: 완료.
LV8: 스무스 블렌드 버전으로 완료, 재검증 트라이얼 진행 중 (첫 완주 확인,
72.5km/h).
컨트롤스탑 규칙: 구현 완료했으나 비활성화 상태 -> 다음 작업에서 실제 CS
시간 데이터 반영 후 재활성화 예정.
