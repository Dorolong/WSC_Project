사용자 요청: "우리 지금까지의 진행상황... release note처럼 저장해서
하나 바뀔때마다 1.0.0부터 시작해서 1.0.1 이런식으로 올려서 지금
버전(string) 릴리즈 노트(button) 하나 나란히 어딘가에 만들어줘."

[ 릴리즈 노트 - 설계 ]
- 사용자가 "꼭 파일이 txt일 필요는 없고, 제목만 각자 버튼(펼치기)이면
  충분"이라고 명시 -> 별도 파일/DB 테이블 없이 app.py 안에 RELEASE_NOTES
  리스트(dict의 리스트: version/date/title/details)로 데이터화.
  progress/, debug_logs/는 이미 훨씬 상세한 "개발자용" 이력이라 별개로
  유지하고, 여기는 "사용자에게 보여줄 요약본"이라는 역할 분리로 접근.
- APP_VERSION = RELEASE_NOTES[0]["version"] (리스트 맨 앞 = 최신 버전).
  새 버전 낼 때마다 리스트 맨 앞에 새 항목 추가하는 규칙.
- UI: 제목 옆 컬럼에 st.caption(f"v{APP_VERSION}") + "릴리즈 노트" 버튼.
  클릭 시 @st.dialog로 각 버전을 st.expander(제목)로 나열 - 펼치면 상세
  내용(details) 표시. "제목 클릭 -> 세부사항" 요구사항을 다이얼로그 중첩
  없이(Streamlit은 다이얼로그 안에 다이얼로그를 못 띄움) expander로 자연
  스럽게 구현.
- 초기 버전 이력(1.0.0~1.0.6)은 오늘 세션 동안 실제로 배포된 기능
  단위로 사용자 친화적 문구로 재구성해서 소급 작성 (첫 배포 -> 로그인/
  기록저장 -> 결과분석 -> 제원설정 격리버그수정 -> 제원 저장/불러오기 ->
  UI개선 -> 이번 릴리즈노트/튜토리얼). progress/ 파일들과 1:1 대응은
  아니고, 개발자 관점 로그를 사용자 관점 요약으로 압축한 것.

[ 튜토리얼 팝업 - 설계 ]
- 닉네임과 같은 패턴으로 Supabase auth user_metadata에
  tutorial_seen(bool) 플래그 저장 - 별도 테이블/컬럼 불필요, 계정에
  귀속되므로 새로고침/재로그인해도 유지.
- 표시 조건 체크는 로그인 버튼의 콜백 안이 아니라 메인 스크립트 흐름
  쪽(제목 렌더링 직전)에 둠 - 로그인 처리 코드는 성공 시 바로
  st.rerun()을 호출해서 그 아래 코드가 같은 실행에서 이어지지 않기
  때문에, "로그인 상태 + 플래그 없음"을 매 스크립트 실행 시 확인하는
  방식으로 구현(플래그가 세팅되고 나면 조건이 거짓이 되어 다시는
  안 뜸).
- 팝업의 "확인했습니다" 버튼 -> supabase.auth.update_user()로
  tutorial_seen=True 기록 -> st.session_state.user 갱신 -> st.rerun().
