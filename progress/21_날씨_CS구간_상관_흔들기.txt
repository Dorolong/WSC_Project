완료일: 2026-07-20 (세션 재개 후)

[ 배경 ]
기존 K=5 로버스트 탐색(common random numbers)은 env_data의 각
포인트(위치 x 날짜 x 시간)마다 완전히 독립적으로
rng.normal(mean, std) 노이즈를 줬음. 사용자가 "바로 옆 포인트에서
일사량이 뜬금없이 팍 감소하는 건 비현실적"이라는 문제 제기 -
실제 날씨는 전선 단위로 공간/시간에 걸쳐 뭉쳐서 움직이는데, 포인트별
독립 노이즈는 그 상관구조를 무시함.

[ 설계 논의 ]
대안으로 논의됐던 것: 요일별로 묶기, CS 구간(leg)별로 묶기 등.
CS 구간 단위로 정착한 이유 - 이미 존재하는 자연스러운 경계(Control
Stop 9개)를 그대로 재사용 가능하고, "이번 leg는 대체로 맑음/흐림"
이라는 직관과도 맞아떨어짐.

[ 구현 - scripts/main.py ]
```python
cs_boundaries = sorted(race.Control_Stop_2025.keys()) + [race.total_distance]
n_segments = len(cs_boundaries)
dist_arr = env_data.index.get_level_values("total_distance_m").to_numpy()
seg_idx = np.clip(np.searchsorted(cs_boundaries, dist_arr, side="right"), 0, n_segments - 1)

for seed in weather_seeds:
    rng = np.random.default_rng(seed=seed)
    z_per_segment = rng.standard_normal(n_segments)  # 세그먼트마다 z값 하나씩
    z_shared = z_per_segment[seg_idx]                # 각 포인트는 자기 세그먼트의 z 공유
    env_data_s["shortwave_radiation"] = (env_data["shortwave_radiation"]
        + z_shared * env_data["shortwave_radiation_std"]).clip(lower=0)
    env_data_s["wind_speed_10m"] = (...).clip(lower=0)
```
핵심은 "포인트마다 별도 z" 대신 "세그먼트마다 z 하나, 그 세그먼트
안 모든 포인트가 그 z를 공유"하는 구조. env_data 포인트가 어느
CS 구간에 속하는지는 searchsorted로 한 번에 벡터 연산.

[ 버그 수정 ]
`.clip(min=0)` -> `.clip(lower=0)`: 설치된 pandas 버전이 Series.clip()의
min=/max= 키워드를 더 이상 지원하지 않고 lower=/upper=를 요구해서
TypeError 발생(scripts/main.py 실행 중 발견). 2곳(shortwave_radiation,
wind_speed_10m) 모두 수정 완료, 재실행 확인함.

[ 실행 결과 - 예비 관찰 ]
2-trial 스모크 테스트(임시 study_name/storage로 실제 study DB 오염
방지) 결과 두 트라이얼 다 5개 날씨 시나리오 평균이 음수(-1.1~-1.2,
즉 대부분 시나리오에서 미완주)로 나옴 - 세그먼트 단위로 날씨를
묶으니 예전(포인트별 독립, 서로 상쇄)보다 훨씬 가혹한 시나리오가
만들어진다는 사용자의 사전 예측("아마 좀 더 열악하게 나오겠지")이
확인됨. 다만 2-trial 무작위 탐색이라 파라미터 자체가 아직 이 새
조건에 최적화 안 된 상태라 단정은 이름. 본 50-trial 탐색은 CS
접근 감속(progress/22) 등 나머지 설계 반영 후 진행하기로 보류.
