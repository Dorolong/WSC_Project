[ scripts/main.py - Optuna 최적화 CLI ]
역할: env_data/route 로드 -> Optuna study 생성/이어하기 -> objective로
n_trials 반복 -> best_params로 최종 재실행 -> outputs/Optuna_result.csv 저장.

현재 탐색 파라미터 (11개, 이름 전면 개편됨):
  v_min(20-60), v_soc_high(60-100)
  soc_ramp_high(0.5-1.0), soc_ramp_low(0.0-0.5)
  slope_k(0-150), radi_para(0-40), radi_risk(0.0-1.0)
  energy_v(0-20), winddir_para(0-20)
  margin_total(0.1-0.6), margin_next_cs(0.1-0.6)
  soc_cutoff(0.00-0.20)
- 기존 LV 번호 기반 키(LV1_V1 등)를 mpc_controller.py 개편에 맞춰
  전부 역할 기반 이름으로 교체.
- LV4_energy_crit, LV7_trend_crit, LV7_look_ahead_para,
  LV7_look_ahead_dist는 LV4+LV7 병합/해석적 유도로 탐색공간에서
  완전히 제거(파라미터 수 16개 -> 11개로 감소).

objective 함수: 완주 시 df["v"].mean()*3.6(양수) 반환, 미완주 시
race_ratio - 2(항상 -1~-2 음수) 반환하는 기본 채점 규칙 유지.

날씨 불확실성 반영 - common random numbers(K=5): 탐색 시작 전
weather_seeds=[1,2,3,4,5]로 5개의 고정된 "흔든 날씨"(env_dicts_fixed)를
미리 만들어두고, objective(trial) 안에서 이 5개 전부에 대해
run_simulation을 돌려 점수를 평균내서 반환. 변경 없음, 안정.

샘플러: optuna.samplers.TPESampler(multivariate=True, group=True).
변경 없음.

**enqueue_trial 제거**: 기존에는 study.enqueue_trial(old_study.
best_params)로 아카이브된 trial_7의 best_params를 매 실행 첫
트라이얼로 강제 큐잉했으나, 파라미터 이름 전면 개편으로 옛 study의
키가 새 탐색공간과 전혀 호환되지 않아(재검증 의미 없음) 삭제. 다음
탐색은 enqueue 없이 처음부터 진행.

storage: sqlite:///outputs/optuna_study.db, study_name="WSC_MPC_Opt".
탐색 파라미터/objective 구조가 바뀔 때마다 outputs/trial_N_YYMMDD/로
옮기고 새로 시작하는 관행 유지. 현재 trial_1~trial_10까지 아카이브됨
(각 폴더에 read.txt로 라운드 요약 기록). trial_10 이후로는 라이브
db가 존재하지 않는 상태(= 이번 라운드는 아카이브 없이 바로 새로
시작 가능).

[ Environment/Open_Meteo_API.py - 환경 데이터 수집 ]
역할: Open-Meteo Archive API(ERA5-Land)에서 기상 데이터를 수집, 연도별
평균+표준편차 계산 후 outputs/env_data.csv로 저장. 변경 없음.

[ app.py (Streamlit 대시보드) - 참고 확인만, 변경 없음 ]
mpc_default_params/study.best_params를 {**...} 형태로 그대로 병합해서
run_simulation()에 넘기는 구조라 파라미터 이름이 바뀌어도 자동으로
새 이름을 따라감. mpc_speed()를 직접 호출하지 않고 run_simulation()을
통해서만 사용하므로 시그니처 변경(state dict 도입) 영향도 없음 확인.
