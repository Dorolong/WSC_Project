파일별 현재 상태: Functions/Vehicle_Function.py

[ 역할 ]
차량 물리 계산(주행저항, 발전량, SOC 갱신)과 전체 시뮬레이션 루프
(run_simulation)를 담당하는 핵심 엔진. 2026-07-20 세션에서
run_simulation() 내부 로직을 6개 헬퍼 함수로 전면 분리 완료.

[ 함수 목록과 현재 상태 ]
- cal_drive_res(step, dt, wind_spd, wind_dir, car_dir): 공기/구름/
  경사/가속 저항 합산 -> (P_batt, a) 반환. **시그니처 변경**: step
  dict + dt를 받아 v/prev_v/theta를 step에서 추출하고, 그 자리에서
  a = (v-prev_v)/dt를 직접 계산해 힘 계산에 쓰고 그대로 반환(호출부가
  a를 따로 다시 구할 필요 없음). dt<=0일 때는 a=0으로 방어(route
  데이터에 거리 중복 지점이 있어 dt=0이 되는 스텝에서 0-나눗셈으로
  nan이 전파되던 버그 수정, 2026-07-20 debug_log 참고).
- gen_solar(): 일사량 -> 태양광 발전량. 변경 없음.
- update_soc(soc, step, dt): OCV-SOC 테이블 보간으로 셀 전압 추정
  후 SOC 갱신. **시그니처 변경**: P_batt/P_gen을 개별 인자 대신
  step dict에서 추출. I_max_chg 단위 버그(mAh->Ah 변환 누락)는
  이전 세션에 수정 완료 상태 유지.
- cs_arrive(): 현재 위치가 CS 20m 이내인지 확인. 변경 없음.
- cs_stop_time_cal(): SOC 기반 정차시간(1800~3600s) 선형 보간. 변경 없음.
- cs_stop_simulation(): CS 정차 중 5분 단위 충전 시뮬레이션.
  **update_soc() 시그니처 변경에 맞춰 호출부 수정**: update_soc(soc,
  {"P_batt": power.P_LV_chg, "P_gen": P_gen_cs_real}, dt_stop) 형태로
  임시 dict를 만들어 전달(정차 중엔 P_batt 자리에 LV 충전 소비,
  P_gen 자리에 태양광 발전을 대입).
- read_path(): CSV 로드 + 경사도/방위각 계산. **2026-07-20(세션
  재개 후) 확장**: slope 계산 후 500m 이동평균(rolling, center=True,
  min_periods=1)으로 스무딩 -> decision_coeff = slope_smooth +
  physics.Crr(소각근사) -> threshold=0.003 기준으로 df["is_downhill"]/
  df["is_uphill"] 불리언 컬럼 추가, return 컬럼 리스트에도 포함.
  목적: CS 접근 코스팅/제동 및 오르막 momentum 로직이 "지금 내리막/
  오르막 구간인지" 판단할 근거 데이터. 상세 설계/검증 과정은
  progress/22 참고.
- light_arrive(curr_dist, light_dists, visited_lights): **신규
  (2026-07-20)**. cs_arrive()와 같은 point-event 패턴이나
  light_dists 값이 dict-unique 보장 안 돼서 enumerate() 인덱스로
  visited 추적. **알려진 버그**: 호출부가 넘기는 curr_dist는 미터
  단위인데 light_dists는 km 단위(traffic_lights_2025.csv 그대로)라
  단위 변환 없이 비교 -> 사실상 항상 매칭 실패, 신호등 지연이
  발동 안 함. progress/20 참고, 아직 미수정.
- compute_speed_limit(step, const): **신규 (2026-07-20)**.
  curr_dist_km = curr_dist/1000 변환 후 np.searchsorted(
  speed_limit_dists, curr_dist_km, side="right")-1로 계단형 룩업.
  light_arrive()와 달리 단위 변환 정상 적용됨. 매 스텝 재평가(점
  이벤트 아닌 구역 판정). progress/20 참고.
- cal_route_vector(step): 두 좌표 사이 방위각(heading) 계산.
  **시그니처 변경**: (lat1,lon1,lat2,lon2) 개별 인자 대신 step을
  받아 prev_lat/prev_lon/curr_lat/curr_lon을 추출(내부 계산은
  범용성 유지 위해 여전히 lat1/lon1/lat2/lon2 이름 사용).
- drivable_hours_until(DY, HR, target_h): 변경 없음, 안정.
- compute_lookahead(step, const): avg_gen_ratio(N-포인트 가중평균) +
  slope_ahead(구간평균 경사 look-ahead) 계산. 이전 세션(07-18)에
  구현 완료된 상태 그대로 유지.

[ run_simulation() 함수분리 - 6/6 완료 (2026-07-20) ]
아래 5개 함수를 이번 세션에 새로 분리 완료(compute_lookahead는
이전 세션에 완료돼 있었음). 상세 설계/버그 이력은
debug_logs/(2026-07-20)_run_simulation_함수분리_5개_완료.txt,
debug_logs/(2026-07-20)_함수분리_및_실행중_발견된_버그_모음.txt
참고.

- **compute_required_pace(step)**: required_race_pace,
  required_next_cs_pace 계산. curr_dist/DY/HR/next_cs/remaining_dist
  전부 step에서 추출, const 불필요(전역 race/drive/
  drivable_hours_until만 사용). (required_race_pace,
  required_next_cs_pace) 튜플 반환.

- **compute_motor_derating(step)**: 전압 디레이팅(omega_wheel,
  backEMP_DC, omega_max) 계산해 v_max_derated 반환. prev_v/
  prev_V_terminal만 필요한 순수 함수.

- **calender_handler(Accum_s)**: 야간 리셋(HR<8 or 17<=HR) + 27일
  초과 체크뿐 아니라 "시간 추정"(total_s=8*3600+Accum_s -> DY/HR
  계산)까지 함수 안으로 통합, Accum_s 하나만 입력. 3-액션 dict 반환:
  - {"Action": "Reset_Go", "Accum_s": ...} : 다음날 08:00으로 점프,
    호출부는 continue
  - {"Action": "Stop"} : 27일 초과, 호출부는 break
  - {"Action": "Go", "Accum_s", "DY", "HR", "total_s"} : 정상 진행

- **control_stop_handler(step, total_s, drive_time_s, Accum_s, soc,
  visited_cs, last_cs_dist, last_cs_time, nearest_diff, env_data)**:
  CS 도착 확인(cs_arrive) + 마감시각 실격 + 구간평균속도(60km/h)
  실격 + cs_stop_simulation() 호출. 3-액션 dict 반환:
  - {"Action": "Go"} : CS 아님, 아무 상태도 안 바뀜
  - {"Action": "Fail"} : 실격, 호출부는 break
  - {"Action": "Stop", "visited_cs", "Accum_s", "soc", "DY", "HR",
    "total_s", "last_cs_dist", "last_cs_time"} : CS 정차 완료, 여러
    상태 갱신
  visited_cs는 set(mutable)이라 파라미터로 받아 .add()만 하면 리턴
  없이도 호출부 원본이 갱신됨(다른 스칼라 상태들과의 차이).
  호출부에서 이 함수는 env_row 조회(nearest_diff, DY, HR)보다
  **먼저** 실행돼야 함 - CS 정차로 시간이 흐르면 DY/HR이 바뀌므로,
  그 이후에 env_row를 조회해야 정차 후 시각의 날씨를 정확히 읽음.

- **compute_vehicle_energy(step, soc, env_row, dt)**: cal_route_vector
  로 vehicle_heading 계산 -> cal_drive_res()로 P_batt/a 계산 ->
  gen_solar()로 P_gen 계산 -> update_soc()로 soc/V_terminal 갱신 ->
  P_net 계산 -> prev_wind_speed/prev_wind_dir/prev_heading 갱신.
  (soc, prev_V_terminal, prev_wind_speed, prev_wind_dir, prev_heading)
  튜플 반환. soc를 명시적 파라미터로 받는 이유: step["soc"]는 루프
  최상단 스냅샷이라 같은 iteration에서 CS 정차로 soc가 이미 갱신된
  경우 stale함 - 호출 시점의 최신 bare soc를 넘겨야 함.

**핵심 설계 원칙(6개 함수 전부 적용) - carry-over 상태는 step에만
두면 안 됨**: step은 매 while 루프 iteration마다 새로 생성되고
버려지는 dict라서, Accum_s/soc/prev_v/prev_a/prev_V_terminal/
prev_wind_speed/prev_wind_dir/prev_heading처럼 다음 스텝으로 이어져야
하는 상태는 반드시 **bare 변수**로 관리해야 함. step["key"]=key
형태로 "읽기용 스냅샷"은 넣을 수 있지만, 실제 갱신(source of truth)은
항상 bare 변수 쪽에서 일어나야 다음 iteration의 step 생성에 반영됨.
반대로 P_batt/P_gen/a/v처럼 "계산 결과를 바로 step에 쓰는" 값들은
step만으로 충분(별도 bare 변수 불필요).

[ run_simulation() 메인 루프 - 그 외 이번 세션 반영 사항 ]
- **mpc_speed(step, params)**: mpc_controller.py도 state -> step
  이름 통일(아래 progress/08 참고), 별도 state dict 생성 없이 step을
  그대로 전달.
- **prev_a carry-over**: cal_drive_res가 계산한 step["a"]를
  compute_vehicle_energy() 호출 직후 prev_a = step["a"]로 bare
  변수에 반영, 다음 iteration의 step 생성 시 a=prev_a로 시딩.
  Configs/Vehicle_Params.py의 simpara.a가 simpara.prev_a로 개명됨에
  맞춰 초기 선언부도 prev_a = simpara.prev_a로 수정.
- **prev_V_terminal 초기값**: 기존 drive.motor_nom_dcV(모터 정격
  입력전압, 배터리 팩 전압과 무관한 값)에서
  np.interp(simpara.soc, cell.ocv_soc, cell.ocv_V) * pack.HV_S
  (SOC=1.0 기준 실제 팩 OCV)로 교체.
- step dict 생성부에 soc/wind_speed/wind_direction/vehicle_heading/
  a 키 전부 포함 완료(이전 세션엔 일부 누락돼 있었음).
- results.append()는 step["DY"]/step["HR"]/step["soc"](스텝 시작
  전 스냅샷, stale)가 아니라 bare DY/HR/soc(이번 스텝 최종 확정값)를
  사용하도록 고정.

[ run_simulation() 종료 사유 추적 (2026-08-02) ]
**리턴 시그니처 변경**: `return pd.DataFrame(results)` 단독에서
`return pd.DataFrame(results), termination_reason`로 변경. 모든
호출부(scripts/main.py 2곳, app.py 1곳)도 튜플 언패킹으로 수정
완료. termination_reason은 루프 시작 전 "완주"로 초기화, 아래 3개
break 지점에서 각각 덮어씀:
- calender_handler()의 "Stop"(27일 초과) - 이제 reason 키로
  "27일 제한기간 초과" 포함해서 반환.
- control_stop_handler()의 "Fail"(CS 마감시각 초과 / 구간평균속도
  미달) - 이제 reason 키로 f"{CS이름} 마감시각 초과" 또는
  f"{CS이름} 구간 평균속도(60km/h) 미달" 포함해서 반환(어느 CS인지
  까지 구분됨).
- soc < simpara.soc_hard_stop - "배터리 SOC 하한 도달" 직접 대입.
목적: app.py에서 AI API 없이 규칙 기반으로 "왜 실패했는지" 분석
패널을 보여주기 위함(상세는 progress/26). 예외적으로 이번엔 사용자가
"둘 다(스펙+구현) 진행하도록 해"라고 명시적으로 요청해서 Claude가
직접 작성.
