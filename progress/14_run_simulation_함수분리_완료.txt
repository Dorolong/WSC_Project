[완료] run_simulation() 함수 분리 (6/6)
================================================================
완료일: 2026-07-20 (1번째 compute_lookahead는 2026-07-18에 선완료)

목표: 200줄 넘는 run_simulation()을 헬퍼 함수로 분리해 가독성 개선.
continue/break가 있는 블록은 "action dict를 리턴하고 실제
continue/break는 메인 루프에 남기는" 패턴으로 분리.

[ 완료된 6개 함수 ]

1. compute_lookahead(step, const) - avg_gen_ratio(N-포인트 가중평균)
   + slope_ahead(구간평균 경사 look-ahead) 계산. (2026-07-18 완료,
   상세는 debug_logs/(2026-07-18)_v_rate_limiting_댐퍼_전환_및_run_simulation_함수분리_착수.txt)

2. compute_required_pace(step) - required_race_pace,
   required_next_cs_pace 계산. curr_dist/DY/HR/next_cs/remaining_dist
   전부 step에서 추출, const 불필요(전역 race/drive/
   drivable_hours_until만 사용).
   초안 버그: next_cs 추출 누락(NameError), return이
   required_race_pace를 빼먹는(튜플 1개만 반환) 버그 - 지적 후 수정.

3. compute_motor_derating(step) - 전압 디레이팅(omega_wheel,
   backEMP_DC, omega_max -> v_max_derated). prev_v/prev_V_terminal만
   필요한 순수 함수, 별다른 버그 없이 깔끔하게 완료.

4. calender_handler(Accum_s) - 원래 계획된 handle_calendar(Accum_s,
   DY, HR)에서 한 단계 더 통합: "시간 추정"(total_s/DY/HR 계산)까지
   이 함수 안으로 흡수해서 Accum_s 하나만 입력받도록 설계 변경.
   이유: step["DY"]/step["HR"]는 루프 최상단 스냅샷이라 이번 스텝
   dt 반영 후의 "진짜 현재 시각"보다 한 스텝 뒤처짐 - 대신 매 스텝
   갱신되는 bare Accum_s를 받아 함수 안에서 매번 새로 계산.
   3-액션 리턴: "Reset_Go"(야간 리셋, Accum_s만 갱신 후 continue) /
   "Stop"(27일 초과, break) / "Go"(정상 진행, Accum_s/DY/HR/total_s
   전부 반환).
   설계 변경 과정: 처음엔 리셋과 정상진행을 둘 다 "Go"로 묶고 dict에
   "Accum_s" 키 유무로 구분하려 했으나, 호출부 가독성 문제로 지적
   후 액션명을 분리(Reset_Go/Go)함.

5. control_stop_handler(step, total_s, drive_time_s, Accum_s, soc,
   visited_cs, last_cs_dist, last_cs_time, nearest_diff, env_data) -
   CS 도착/마감시각/구간평균속도 실격 체크 + cs_stop_simulation
   호출. "Fail"(실격, break) / "Stop"(정차 완료, 여러 값 갱신) /
   "Go"(CS 아님, 아무것도 안 바뀜) 3-액션.
   **초안 버그 3종** (전부 지적 후 수정):
   - visited_cs = set()로 함수 안에서 매번 새로 생성 -> 누적 방문
     기록이 매 호출마다 사라짐. visited_cs를 파라미터로 받아야 함
     (set은 mutable이라 .add()만 하면 리턴 없이도 호출부 원본에
     반영됨, Accum_s/soc 같은 스칼라와의 차이).
   - last_cs_dist/last_cs_time/Accum_s/soc를 파라미터로도 안 받고
     함수 내부에서 정의도 안 한 채 참조 -> NameError. 전부 파라미터로
     추가.
   - CS 정차가 실제로 일어났을 때 갱신된 Accum_s/soc/DY/HR/total_s를
     리턴에 안 담아 호출부가 못 받는 문제 -> 리턴 dict에 추가.
   - "Action": "Stop"이 calender_handler의 "Stop"(시뮬레이션 종료)과
     의미가 완전히 다른데 이름이 겹침(여기서는 "CS 정차 완료") -
     서로 다른 result 변수(cs_stop_result vs calender_result)에
     담겨서 실제 충돌은 없지만 가독성 문제로 지적, 사용자는 현재
     이름 유지 선택.
   **호출 순서 버그**: 초안에서 env_row 조회(nearest_diff, DY, HR)가
   control_stop_handler() 호출보다 먼저 있어서, CS 정차로 시간이
   흘러 DY/HR이 바뀌어도 env_row는 정차 전 시각의 날씨를 씀(리팩터링
   전 원본 코드는 CS 처리 -> env_row 조회 순서였음). 지적 후 순서
   교정 완료.

6. compute_vehicle_energy(step, soc, env_row, dt) - cal_route_vector
   /cal_drive_res/gen_solar/update_soc 호출 + P_net 계산 + prev_wind/
   heading 갱신을 한 함수로 통합, (soc, prev_V_terminal,
   prev_wind_speed, prev_wind_dir, prev_heading) 튜플 반환.
   **초안 버그**: 함수 시그니처에 soc가 없는데 내부에서
   update_soc(soc, ...) 호출 -> NameError. step["soc"]로 대체해도
   안 되는 이유까지 확인: step["soc"]는 루프 최상단 스냅샷이라
   같은 iteration에서 CS 정차로 soc가 이미 갱신됐다면 stale한 값
   (DY/HR과 동일한 문제 패턴). soc를 명시적 파라미터로 추가해
   호출 시점의 최신 bare soc를 넘기도록 수정.

[ mpc_speed() 시그니처 정리 ]
mpc_speed(state, params) -> mpc_speed(step, params)로 파라미터명
일괄 변경. run_simulation()이 별도 state dict를 안 만들고 step을
그대로 전달하는 구조로 이미 바뀌어 있었는데, 함수 쪽 파라미터명만
"state"로 안 맞았던 것 정리(본문 내 state["..."] 21곳 전부
step["..."]로 교체). 동작 변화 없음, 순수 명명 일관성.

[ 핵심 설계 원칙 - carry-over 상태는 step에만 두면 안 됨 ]
step은 매 while 루프 iteration마다 새로 생성되고 버려지는 dict라서,
Accum_s/soc/prev_v/prev_a/prev_V_terminal/prev_wind_speed/
prev_wind_dir/prev_heading처럼 다음 스텝으로 이어져야 하는 상태는
반드시 **bare 변수**로 관리해야 함. step["key"]=key 형태로 "읽기용
스냅샷"은 넣을 수 있지만, 실제 갱신(source of truth)은 항상 bare
변수 쪽에서 일어나야 다음 iteration의 step 생성에 반영됨. 이번
세션 버그의 상당수(prev_V_terminal, prev_a 등)가 이 원칙을 놓쳐서
발생 - 자세한 버그 목록은 progress/15 참고.

[ 결과 ]
run_simulation() 라인 수는 200줄대 -> 약 160줄대로 축소(애초
목표였던 100줄 이내는 아직 미달 - step dict 생성부 자체가 20줄
남짓 차지하는 구조적 이유가 있어, 추후 100줄 목표를 유지할지
재검토 필요할 수 있음).
