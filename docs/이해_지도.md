## 0. 먼저 — 이 프로젝트에서 내 것과 남의 것

프로젝트 규칙(`CLAUDE.md`)에 **"물리·의사결정 로직은 사용자가 직접
작성한다"**가 있고, 이게 계속 지켜졌다. 그래서 지금 이해도 지형은 이렇다.

| 층 | 영역 | 상태 |
|---|---|---|
| L1 | 문제 정의·차량 물리 | 직접 작성 — **이해 유지됨** |
| L2 | MPC 제어 로직 | 직접 작성 — **이해 유지됨** |
| L3 | Optuna 최적화 | 함께 논의하며 결정 — 대체로 앎 |
| L4 | 데이터 파이프라인 | 함께 작업 — 대체로 앎 |
| L5 | 웹 앱 / 인증 | 에이전트 주도 — **부분 공백** |
| L6 | 서버·배포·보안 | 에이전트 주도 — **주요 공백** |

**핵심 판단: 프로젝트의 심장(L1~L2)은 여전히 내 것이다.** 공백은
L5~L6이고, 이건 "태양광차 프로젝트 지식"이 아니라 **일반적인 웹 인프라
지식**이다. 범위가 특정된다는 건 좋은 소식이다.

### 깊이의 3단계

모든 것을 같은 깊이로 알 필요는 없다. 아래 표기를 쓴다.

- 🟥 **직접 고칠 수 있어야** — 내가 설계했거나 앞으로 고칠 부분
- 🟨 **설명할 수 있어야** — 남이 물으면 왜 그런지 답할 수 있어야 하는 것
  (연구과제·포트폴리오라 실제로 물어본다)
- ⬜ **블랙박스로 둬도 됨** — 동작만 알면 되고, 필요할 때 찾아보면 되는 것

### 구조가 지금 두 벌인 이유

### 🟨 반드시 이해해야 할 개념 3개

**(1) access token vs refresh token**
로그인하면 Supabase가 두 개를 준다.
- **access token** — API 호출에 붙이는 출입증. **1시간이면 만료**된다.
- **refresh token** — 만료된 출입증을 새로 받아오는 교환권. 오래 간다.

*실제로 난 사고*: `state.js`가 로그인 순간의 access token을 붙잡아 계속
재사용했다. 페이지를 1시간 넘게 열어두면 이후 모든 호출이 401이 됐다.
**단서는 폴링이 연속으로 401을 낸 것**이었다 — 일회성 경합이면 그런
모양이 안 나온다.

**(2) RLS와 GRANT는 다른 것이다**
Supabase(=PostgreSQL)에서 내 데이터를 지키는 장치가 두 겹이다.
- **GRANT** — "이 역할이 이 테이블을 만질 수 있는가" (문을 열어주는 것)
- **RLS 정책** — "만질 수 있다면, 어느 줄까지인가" (내 줄만 보이게)

*증상으로 구분한다*:
```
RLS 정책이 없으면      → 빈 배열 200   (문은 열렸는데 볼 게 없음)
테이블 GRANT가 없으면  → 401           (문 자체가 안 열림)
```
`optuna_runs`에서 GRANT가 빠져 있어 401이 났었다. 증상이 다르니
원인 추적에 쓸 수 있다.

**(3) anon key는 숨기는 값이 아니다**
`server/static/sync-config.js`가 브라우저로 그대로 내려간다. 누구나
개발자 도구로 볼 수 있다. 환경변수로 옮겨도 이 사실은 안 변한다.
→ **진짜 보안 경계는 RLS다.** anon key는 "이 프로젝트에 요청할 수 있다"는
표시일 뿐, "무엇을 볼 수 있다"를 정하는 건 RLS다.
(반면 `service_role` 키는 RLS를 우회하므로 절대 클라이언트에 두면 안 된다.)

## L6. 서버·배포·보안 🟨 ← 주요 공백

| 파일 | 줄 수 | 역할 |
|---|---|---|
| `server/main.py` | 854 | API·대기열·진행률·상태 영속화 |
| `server/sim_runner.py` | 200 | 시뮬레이션 실행 프로세스 |
| `server/study_runner.py` | 237 | Optuna 탐색 실행 프로세스 |
| `server/Caddyfile` | — | HTTPS·보안 헤더 |
| `server/wsc-launcher.service` | — | 재부팅 시 자동 기동 |

### 요청 하나가 지나가는 길

```
브라우저 ──HTTPS──> Caddy(443) ──평문──> uvicorn(127.0.0.1:8000) ──> FastAPI
                     인증서 자동발급        외부에서 직접 접근 불가
                     보안 헤더 부착
```

**왜 이렇게 나눴나**: Caddy는 HTTPS(암호화·인증서)만 담당하고, 파이썬은
로직만 담당한다. 파이썬이 직접 443을 열면 인증서 갱신까지 떠안아야 한다.

**왜 8000 포트를 닫았나**: 안 닫으면 `http://IP:8000`으로 들어오는 평문
경로가 살아있어서 HTTPS를 세운 의미가 없어진다. 방화벽에서도 막고
(`--host 127.0.0.1`) 바인딩도 로컬로 제한해서 **두 겹**으로 막았다.

### 🟨 개념 카드

**HTTPS가 실제로 막아준 것**
예전 주소는 `http://161.33.149.239:8000`이었다. Supabase 로그인 자체는
https라 안전했지만, 받은 access token을 **우리 서버로 보낼 때**
`Authorization: Bearer ...`가 평문으로 나갔다. 같은 네트워크에 있는
사람이 그걸 주워 내 계정으로 API를 호출할 수 있었다.

**HSTS — 되돌리기 비싼 설정**
"이 사이트는 앞으로 무조건 HTTPS로만 접속하라"고 브라우저에 기억시키는 것.
`max-age`는 만료 날짜가 아니라 **슬라이딩 윈도**다(방문할 때마다 타이머
재시작). 길게 박아두면 인증서가 깨졌을 때 그 기간 내내 우회 접속이
불가능해진다. 그래서 판단 기준은 "며칠 지났나"가 아니라
**"인증서 자동 갱신을 한 번 통과했나"**다.

**왜 별도 프로세스(subprocess)인가**
`study.optimize()`는 끝날 때까지 멈춰 있는(블로킹) 호출이다. FastAPI
안에서 돌리면 다른 사람 요청까지 막힌다. 스레드로 나눠도 **GIL** 때문에
CPU를 쓰는 순수 파이썬 루프는 진짜 병렬이 안 된다. → OS 프로세스를 분리.

**systemd**: 리눅스에서 프로그램을 서비스로 등록해 재부팅 후에도 자동으로
켜지게 하는 장치. `git pull` 후 `systemctl restart wsc-launcher`를 해야
서버에 실제 반영된다. **머지만 하고 이걸 빠뜨려 "고쳤는데 왜 그대로냐"가
된 적이 있다.**

## 반복해서 등장한 교훈 3개

이 프로젝트에서 **같은 종류의 사고가 반복**됐다. 이건 개별 버그가 아니라
패턴이라 외워둘 값어치가 있다.

**1. 전역 상태는 여러 사용자를 섞는다 (2회 발생)**
Streamlit Cloud는 여러 사용자가 **서버 프로세스 하나를 공유**한다. 모듈
전역 객체를 고치면 그 순간 접속 중인 **모든 사용자**의 결과가 바뀐다.
→ 그래서 설정을 `cfg` → `const`로 **인자 전달**한다.
1차는 차량 제원 전체(`progress/28`), 2차는 `simpara` 하나가 남아 있던
것(`progress/36`).

**2. 단위 불일치는 조용히 실패한다**
`light_arrive()`가 미터와 km를 비교해서 신호등 지연이 **한 번도 발동하지
않았다.** 에러가 안 나니 몇 주 동안 몰랐다. 고치고 나니 도달거리가
1,920m 줄었다(정상 — 이제 실제로 지연이 걸린다).

**3. 문서와 코드가 어긋난다**
`progress/48`이 "SETUP.md에 SQL을 정리했다"고 적었지만 실제로는 없었다.
한 세션은 `app.py`를 449줄로 잘못 읽고(실제 948줄) 이미 고친 버그를
"미해결"이라고 보고했다.
→ **문서를 신뢰하되 코드로 교차 확인한다.**

## 지금 공백을 메우는 순서

1. **L5의 개념 3개**(토큰 / RLS·GRANT / anon key) — 이게 최근 버그 대부분의
   배경이고, 보안 후속 작업(`docs/codex_security_tasks.txt`)을 읽으려면 필수
2. **L6의 요청 경로** — 브라우저부터 FastAPI까지 한 번 따라가 보기
3. **자가 점검 1~5번**(설계 판단) — 답이 전부 `총괄기획안 PDF`와
   `progress/`에 있다. 찾아서 답해보면 그 자체가 복습이 된다
4. 그 다음에 L2로 돌아가 **비용함수 MPC 전환** 준비
   (백로그의 다음 큰 방향)

## 이 문서 갱신 규칙

새로운 층위가 생기거나(예: AI 예측 모델, 강화학습) 공백이 메워지면
해당 절의 🟥🟨⬜ 표기를 갱신할 것. 이 문서는 **완성본이 아니라 현재
이해도의 스냅샷**이다.
