02

요청 하나가 지나가는 길

브라우저가 버튼을 누른 순간부터 파이썬이 답할 때까지. 각 칸이 나뉘어 있는 데는 이유가 있다.

브라우저
HTTPS 요청
Supabase에서 받은 출입증(access token)을 헤더에 붙여 보낸다.
:443
Caddy
인증서 자동 발급·갱신과 보안 헤더만 담당. 파이썬이 이걸 떠안지 않게 분리했다.
127.0.0.1:8000
uvicorn
바깥에서 직접 못 닿는다. 방화벽과 바인딩 두 겹으로 평문 경로를 막았다.
FastAPI
검증 · 대기열
출입증을 Supabase에 되물어 확인하고, 무거운 일은 큐에 넣는다.
subprocess
계산
시뮬레이션·탐색은 별도 프로세스. 한 사람의 계산이 남의 요청을 막지 않는다.

왜 8000 포트를 닫았나 — 열어두면 http://IP:8000으로 들어오는 평문 경로가 살아 있어 HTTPS를 세운 의미가 사라진다. 실제로 그 상태였을 때 출입증이 암호화 없이 오갔다.

03

시뮬레이션 한 스텝

경로를 20m 간격으로 쪼개 약 15만 번 반복한다. 아래가 그 한 번에 일어나는 일이다.

경로·기상 조회
  → 앞구간 예측 (향후 발전량 · 경사)
  → 필요 페이스 (전체 완주 · 다음 컨트롤스탑)
  → 모터 상한 (SOC가 낮으면 전압이 떨어져 최고속도가 준다)
  → mpc_speed() ← 권장속도 결정
  → 소요시간 계산 → 야간 경계 검사 → 컨트롤스탑 정차
  → 종료조건 (SOC 하한 · 마감시각 · 구간평균속도 · 27일)
  → 주행저항과 발전량으로 SOC 갱신

지금 이 제어기의 한계 — mpc_speed()는 SOC·경사·일사량·에너지예산·바람을 각각 규칙으로 보정해 더한 뒤 상한으로 자른다. 비용함수를 실제로 푸는 것이 아니라 잘 튜닝된 규칙으로 근사하는 구조다.

다음 큰 방향은 이 규칙들을 비용함수와 제약조건으로 재구성하는 것이고, 그러면 지금의 보정항 대부분이 사라진다 — 경사·바람·일사량은 물리 모델 안으로 흡수되고, 제약은 사후 클리핑이 아니라 최적화 내부에서 다뤄진다.

04

계층별 파일과 이해도

전부 같은 깊이로 알 필요는 없다. 프로젝트 규칙상 물리·제어 로직은 직접 작성해왔고, 최근 빠르게 만들어진 웹·인프라 쪽이 공백이다.

층영역파일줄이해도
L1문제와 물리 Functions/Vehicle_Function.py709 직접 고칠 수 있어야
L2MPC 제어 mpc/mpc_controller.py116 직접 고칠 수 있어야
L3Optuna 최적화 scripts/main.py229 설명할 수 있어야
L4데이터 파이프라인 Environment/ · Configs/*.csv— 설명할 수 있어야
L5웹 앱 · 인증 server/static/js/ · shared/cfg_serde.py1,079 공백 — 개념 3개부터
L6서버 · 배포 · 보안 server/main.py · Caddyfile · *.service854 주요 공백
직접 고칠 수 있어야 — 내가 설계했고 앞으로도 고칠 부분 설명할 수 있어야 — 남이 물으면 답할 수 있어야 하는 것 블랙박스 — 동작만 알면 되는 것 (ACME 절차, ASGI 내부, Plotly 렌더링)

공백을 메우는 순서 — L5의 개념 세 가지가 최근 버그 대부분의 배경이다: 출입증과 갱신권의 차이(오래 열어두면 401이 나던 이유), 테이블 접근권과 행 단위 잠금의 차이(권한이 없으면 401, 잠금이 없으면 빈 결과 — 증상이 다르다), 공개키가 공개여도 되는 이유(진짜 경계는 행 단위 잠금 쪽이다).

05

세 번 반복된 사고 패턴

개별 버그가 아니라 패턴이다. 구조를 이해하는 데 이게 제일 빠른 지름길이다.

전역 상태는 사용자를 섞는다 2회 발생

여러 사용자가 서버 프로세스 하나를 공유한다. 모듈 전역 객체를 고치면 그 순간 접속 중인 모든 사람의 결과가 바뀐다. 그래서 설정을 전역이 아니라 인자로 전달한다. 1차는 차량 제원 전체, 2차는 시뮬레이션 파라미터 하나가 남아 있던 것.

단위 불일치는 조용히 실패한다

신호등 판정이 미터와 킬로미터를 비교하고 있어서 한 번도 발동하지 않았다. 에러가 없으니 몇 주 동안 몰랐다. 고치고 나니 도달거리가 1,920m 줄었다 — 정상이다.

문서와 코드가 어긋난다

"정리했다"고 기록됐지만 실제로는 안 된 항목이 있었고, 한 세션은 파일을 절반만 읽고 이미 고친 버그를 미해결로 보고했다. 문서를 신뢰하되 코드로 교차 확인한다.

이 문서는 저장소의 docs/구조도.html이다. 글로 된 학습 경로는 docs/이해_지도.md, 설계 근거 전체는 docs/WSC_DriveEff_총괄기획안.pdf, 지금 할 일은 progress/의 가장 큰 번호에 있다.
